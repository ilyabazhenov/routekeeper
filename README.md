# Routekeeper

**Каждому приложению — свой путь.**

Routekeeper — файрвол и маршрутизация через прокси для macOS в одном правиле.
За каждое исходящее соединение он решает, что с ним делать: пустить напрямую,
отправить через прокси, сбросить или спросить вас. Telegram — через SOCKS5,
рабочий Slack — напрямую, незнакомый бинарник — в тупик.

## Что умеет

- **Правило «приложение + куда → действие».** Действия: напрямую, через прокси,
  в тупик, спросить. Простой случай — в один клик: перетащите `.app`
  и выберите прокси.
- **Весь состав, а не только паровоз.** Правило на приложение действует
  на его helper-процессы и дочерние процессы. Приложения узнаются по подписи
  разработчика, а не по имени файла.
- **Прокси SOCKS5 и HTTP CONNECT**, с логином и паролем или без. Имя хоста
  резолвит прокси, а не ваш провайдер. Строку вида `socks5://user:pass@host:port`
  можно просто вставить.
- **Четыре режима файрвола.** «Только прокси» (по умолчанию, без вопросов),
  «Спрашивать», «Тихий», «Блокировать всё».
- **Окно-вопрос**, когда в режиме «Спрашивать» появляется соединение без
  правила: один вопрос на процесс, с подписью, путём и цепочкой родителей.
  Ответ становится правилом — для одного адреса, порта или любого адреса;
  один раз, до выхода из приложения или навсегда.
- **Монитор соединений** в реальном времени: приложение, адрес, сработавшее
  правило, путь, трафик, ошибки. Из любой строки можно создать правило.
- **Детектор утечек.** Отмечает DNS, UDP/QUIC и процессы, которые ушли мимо
  прокси у приложений, которые должны ходить через прокси, и подсказывает,
  как это исправить.
- **Fail-closed.** Если прокси недоступен, соединение получает отказ, а не уходит
  напрямую. Иначе — только если вы сами это включили.
- **Меню-бар.** Включение, режим, внешний IP через прокси, приложения
  с тумблерами.

## Чего не умеет

- Через прокси идёт только TCP. UDP и QUIC у проксируемых приложений
  блокируются — браузеры и мессенджеры переходят на TCP сами.
- Только SOCKS5 и HTTP CONNECT. Shadowsocks, VLESS и прочие протоколы — нет.
- Если приложение подключается по IP без имени хоста, правила по домену к нему
  не применяются.
- Только исходящие соединения.
- Нет профилей, цепочек прокси и переключения на запасной прокси.
- Интерфейс пока только на русском.

## Приватность

Routekeeper не собирает телеметрию и никуда не отправляет данные о том,
куда ходит ваш Mac. Журнал соединений живёт в памяти и на диск не пишется.
Правила и пароли прокси хранит системное расширение в файле, доступном только
root. Подробно — в [политике конфиденциальности](docs/privacy.md).

## Обратная связь

Нашли ошибку или не хватает функции — [откройте issue](../../issues).
Если Routekeeper что-то сломал в сети, приложите вывод:

```bash
log show --last 15m --predicate 'subsystem BEGINSWITH "dev.ilyabazenov"' > routekeeper.log
```

Перед отправкой просмотрите файл: в нём есть адреса, к которым ходили
ваши приложения.
