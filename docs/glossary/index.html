Прокси

Прокси (прокси-сервер)

Сервер-посредник между вашим Mac и сайтом. Приложение отправляет соединение прокси, а тот подключается к сайту от своего имени. Поэтому сайт видит IP-адрес прокси, а не ваш. В отличие от VPN, прокси работает не для всего Mac, а только для соединений, которые к нему направили.

В Routekeeper: вы решаете, какие приложения и сервисы идут через прокси; сами прокси добавляются в разделе Прокси — см. «Прокси».

SOCKS5

Универсальный протокол прокси: передаёт любое TCP-соединение, не вникая в его содержимое. Его часто открывают клиенты, работающие на этом же Mac, например на адресе 127.0.0.1:1080. Сам SOCKS5 соединение с прокси не шифрует, поэтому для прокси где-то в интернете удобнее HTTPS-прокси.

В Routekeeper: тип SOCKS5, порт по умолчанию 1080. Строки socks5://, socks5h://, socks:// и строка без схемы считаются SOCKS5.

HTTP-прокси (HTTP CONNECT)

Прокси, с которым приложение разговаривает по HTTP. Командой CONNECT оно просит прокси открыть туннель к нужному сайту и порту, а дальше данные идут как есть. Сайты по HTTPS остаются зашифрованными, но само соединение с прокси не шифруется: логин, пароль и имена сайтов видны по пути. Такие прокси часто стоят в офисных сетях.

В Routekeeper: тип HTTP, порт по умолчанию 8080. Авторизация — только по логину и паролю (Basic); NTLM, Kerberos и PAC-файлы не поддерживаются.

HTTPS-прокси

Тот же HTTP CONNECT, но соединение с прокси защищено TLS, как сайт с https://. По пути не видны ни логин с паролем, ни имена сайтов, которые вы открываете. Сервер подтверждает, что он настоящий, сертификатом, выданным на его доменное имя.

В Routekeeper: тип HTTPS, порт по умолчанию 443. В поле Сервер указывайте домен, а не IP: по нему проверяется сертификат. Такой прокси на своём сервере ставит скрипт со страницы «Свой прокси-сервер».

Fail-closed: прокси недоступен — соединения не уходят напрямую

Так называют поведение, при котором сбой ничего не открывает. Если прокси недоступен, соединение обрывается, а не уходит напрямую. Приложение покажет ошибку сети, зато ваш настоящий адрес не раскроется. Обратное поведение называют fail-open.

В Routekeeper: так устроено по умолчанию; пускать напрямую при недоступном прокси можно включить в Настройки → Сеть → Если прокси недоступен — пускать напрямую. Исключения: DNS по UDP, UDP при выключенном Блокировать UDP и QUIC и пара секунд при перезапуске или обновлении расширения — см. ограничения.

Сервер и адреса

VPS

Виртуальный сервер, который арендуют у хостинг-провайдера, обычно помесячно. У него свой постоянный публичный IP-адрес и, как правило, Linux, например Debian или Ubuntu. Управляют им удалённо, через SSH.

В Routekeeper: на VPS можно поставить свой HTTPS-прокси одним скриптом — см. «Свой прокси-сервер».

SSH

Защищённый способ управлять сервером из Терминала на Mac: вы вводите команды, а выполняются они на сервере. Подключение выглядит так: ssh root@203.0.113.7 — имя пользователя, @ и адрес сервера. При первом подключении SSH показывает отпечаток ключа сервера и спрашивает, доверять ли ему.

В Routekeeper: SSH нужен один раз, чтобы запустить на сервере скрипт установки прокси — см. «Свой прокси-сервер».

Домен (доменное имя)

Имя сайта или сервера, удобное для людей, например example.com. Поддомен — имя внутри домена: proxy.example.com. Домены покупают у регистратора, бывают и бесплатные имена вида my-name.duckdns.org.

В Routekeeper: HTTPS-прокси нужен домен, а правила можно писать по доменам — см. домен для своего сервера и как записать адрес в правиле.

A-запись

Запись в DNS, которая связывает доменное имя с IPv4-адресом. По ней компьютеры узнают, что proxy.example.com — это, например, 203.0.113.7. Её создают там, где управляют доменом; новая запись обычно начинает работать за несколько минут.

В Routekeeper: для своего сервера A-запись домена должна указывать на IP вашего VPS, иначе сервер не получит сертификат — см. «Свой прокси-сервер».

IP-адрес

Числовой адрес устройства в сети: IPv4 вида 203.0.113.7 или IPv6 вида 2001:db8::1. Внешний IP — адрес, с которым ваше подключение видят сайты; дома это обычно адрес провайдера. Через прокси сайты видят IP прокси.

В Routekeeper: внешний IP прокси показан в меню значка и после кнопки Проверить; в правилах можно указать IP-адрес или подсеть.

Порт

Номер, по которому на одном адресе различают разные службы, как номер квартиры в доме. Сайты по HTTPS работают на порту 443, по HTTP — на 80, DNS — на 53.

В Routekeeper: у прокси есть порт (по умолчанию 1080 для SOCKS5, 8080 для HTTP, 443 для HTTPS), а правило можно ограничить портом, например «порт 443 · UDP».

Как ходят данные

TCP

Способ передачи данных с установкой соединения и подтверждением доставки: если кусочек потерялся, его отправят снова. На TCP работают сайты, почта и большинство приложений.

В Routekeeper: через прокси идёт именно TCP.

UDP

Способ передачи без соединения и подтверждений: данные просто отправляются. Это быстрее, поэтому UDP используют звонки, видео в реальном времени, игры, DNS и QUIC.

В Routekeeper: прокси SOCKS5, HTTP и HTTPS не передают UDP, поэтому у приложений через прокси он блокируется или идёт напрямую с пометкой — см. «UDP и QUIC».

QUIC

Современный способ загружать сайты поверх UDP, на нём работает HTTP/3. Браузеры используют его там, где сайт это поддерживает. Если QUIC недоступен, браузер незаметно переходит на обычный HTTPS по TCP.

В Routekeeper: переключатель Блокировать UDP и QUIC выключает QUIC у приложений через прокси, и браузеры переходят на TCP, который идёт через прокси.

DNS

Справочная служба интернета: переводит имя вроде example.com в IP-адрес. Обычно запросы уходят провайдеру или роутеру, и они видят, какие имена спрашивает ваш Mac. Обычные DNS-запросы идут по UDP на порт 53 и не шифруются.

В Routekeeper: DNS через прокси передаёт прокси имя сайта, чтобы адрес узнал он; что при этом идёт мимо прокси — см. «DNS».

DoH (DNS через HTTPS)

DNS-запросы внутри обычного зашифрованного HTTPS-соединения. По пути не видно, какие имена вы спрашиваете. В браузерах это включается в настройках, параметр называется «DNS через HTTPS» или «безопасный DNS».

В Routekeeper: если браузер целиком идёт через прокси, его DoH-запросы идут через прокси вместе с остальным трафиком; так пропадают пометки «DNS мимо прокси» у браузера — см. рецепт.

TLS

Шифрование соединения, на котором работает https:// в адресной строке. Оно скрывает содержимое от всех по пути и с помощью сертификата подтверждает, что вы говорите именно с тем сервером, чьё имя указано. Сертификат выдаётся на доменное имя, например бесплатно от Let's Encrypt.

В Routekeeper: HTTPS-прокси шифрует TLS соединение с прокси; если сертификат не совпадает с именем в поле Сервер, проверка покажет «Не удалось подключиться к прокси: TLS: сертификат прокси не прошёл проверку».

Mac и приложения

Сетевое расширение

Модуль, через который программа может фильтровать и направлять сетевые соединения в macOS. Он устанавливается как системное расширение: отдельно от окна приложения и только с разрешения пользователя. Расширение работает от имени системы, поэтому продолжает работать, даже когда окно закрыто.

В Routekeeper: расширение называется Routekeeper Extension (в версии 0.2.1 — Routekeeper Network Extension), его состояние видно в Настройки → Расширение — см. «Из чего состоит Routekeeper».

Дочерний процесс

Программа, которую запустила другая программа. Терминал запускает git, curl и npm. Браузеры и мессенджеры запускают вспомогательные процессы, и через них идёт почти весь их трафик.

В Routekeeper: Вместе с дочерними процессами включено по умолчанию: маршрут приложения действует на его вспомогательные процессы и на всё, что оно запускает — см. «Приложения и сервисы».

Подпись кода

Цифровая подпись, которую разработчик ставит на свою программу. По ней видно, кто выпустил программу (Team ID разработчика) и что это за программа (идентификатор вида com.example.app). Если программу изменить после подписи, подпись перестанет сходиться.

В Routekeeper: приложения узнаются по подписи, а не по имени файла: переименованная программа не попадёт под чужое правило, а правило переживает обновление приложения. Программы без подписи узнаются по пути к файлу.

localhost (loopback)

Адреса, по которым Mac обращается сам к себе: 127.0.0.1, ::1 и имя localhost. Такие соединения не выходят в сеть. Например, по ним приложения подключаются к клиенту прокси, запущенному на этом же Mac.

В Routekeeper: соединения с самим Mac идут напрямую — так задают встроенные правила и настройка Настройки → Сеть → Не трогать localhost.

Адреса в правилах

Подсеть (CIDR)

Запись диапазона IP-адресов: адрес, косая черта и длина префикса. 10.0.0.0/8 — все адреса от 10.0.0.0 до 10.255.255.255, 192.168.1.0/24 — от 192.168.1.0 до 192.168.1.255. Чем больше число после черты, тем уже диапазон.

В Routekeeper: подсеть можно указать в правиле, а в некоторые сервисы подсети уже входят, например адреса Telegram — см. как записать адрес в правиле.

Шаблон *.домен

Звёздочка вместо любого поддомена. Без звёздочки правило подходит только для одного имени, со звёздочкой — для целого семейства имён.

В Routekeeper: *.example.com подходит и для самого example.com, и для всех его поддоменов любой глубины, например a.b.example.com; более длинный шаблон точнее, поэтому *.mail.example.com важнее *.example.com.
