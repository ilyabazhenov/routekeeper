Свой прокси-сервер за 15 минут

Одна команда превращает арендованный VPS в HTTPS-прокси для Routekeeper. Снаружи сервер выглядит как обычный сайт, а ключ от прокси есть только у вас.

Редакция от 4 октября 2026 года.

Что получится

Приложение → Routekeeper → TLS → ваш сервер :443 → интернет
  • HTTPS-прокси: HTTP CONNECT внутри TLS на Caddy с forwardproxy@naive. На Mac, кроме Routekeeper, ничего ставить не нужно.
  • Сертификат Let's Encrypt. Без пароля сервер отвечает как обычный сайт-заглушка и не выдаёт, что он прокси.
  • Сервер ваш. Скрипт ничего никуда не отправляет: ни трафик, ни пароль не проходят через Routekeeper или его автора.
  • Только TCP. Звонки и голос через такой прокси не пойдут, подробнее — в ограничениях.

Что понадобится

  • VPS с Debian 12 или 13 либо Ubuntu 24.04, процессор x86_64 (amd64), от 1 ГБ памяти, публичный IPv4 и доступ root по SSH. Подойдёт самый простой тариф.
  • Ближе — быстрее. Каждое новое соединение занимает примерно три пинга до сервера, поэтому выбирайте ближайшую страну, где работают нужные вам сервисы.
  • Свободные порты 80 и 443. Если на сервере уже работает сайт или VPN-панель (nginx, Xray, 3x-ui, Marzban), скрипт его не тронет — возьмите отдельный сервер.
  • Домен. Свой или бесплатный на DuckDNS: по нему Let's Encrypt выдаёт сертификат.

1Домен

Для бесплатного домена на DuckDNS:

  1. Войдите на duckdns.org через GitHub или Google.
  2. Создайте поддомен. Лучше нейтральное имя, без «proxy» и «vpn».
  3. В поле current ip впишите IP сервера и нажмите update ip.

Токен DuckDNS не понадобится: IP сервера постоянный. Для своего домена создайте у регистратора A-запись с IP сервера. Запись начинает работать через пару минут.

2Вход на сервер

Откройте Терминал (Программы → Утилиты) и подключитесь, подставив IP из письма хостера:

ssh root@IP

На вопрос о «fingerprint» ответьте yes, затем введите пароль root. Символы пароля при вводе не отображаются — так и должно быть.

3Установка

На сервере выполните одну команду, подставив свой домен:

curl -fsSL https://getroutekeeper.app/server.sh | bash -s -- --domain имя.duckdns.org

Если хостер выдал не root, а пользователя с sudo, пишите | sudo bash -s --. Установка занимает минуту-две. Скрипт:

  1. проверяет, что домен указывает на этот сервер, а порты 80 и 443 свободны;
  2. ставит Caddy с forwardproxy@naive и сверяет контрольную сумму сборки;
  3. создаёт логин и длинный случайный пароль;
  4. получает сертификат Let's Encrypt и ставит сайт-заглушку для всех, кто приходит без пароля;
  5. включает BBR — он заметно ускоряет соединения на дальних маршрутах;
  6. ставит fail2ban, который блокирует подбор паролей к SSH;
  7. включает автоматические обновления безопасности (сервер при этом сам не перезагружается);
  8. проверяет, что прокси работает, и печатает строку для Routekeeper.

Скрипт из интернета разумно прочитать перед запуском. Тогда так:

curl -fsSLO https://getroutekeeper.app/server.sh
less server.sh
bash server.sh --domain имя.duckdns.org
ФлагЧто делает
--new-passwordСоздаёт новые логин и пароль.
--no-bbrОставляет настройки TCP как есть.
--no-fail2banНе ставит fail2ban.
--no-auto-updatesНе включает автоматические обновления.
--uninstallУдаляет прокси. BBR, fail2ban и обновления остаются.
--lang ruСообщения на русском, если скрипт заговорил по-английски.

4Routekeeper

В конце скрипт печатает строку вида https://u1a2b3c…:…@имя.duckdns.org:443.

  1. Выделите строку в Терминале и скопируйте её (⌘C).
  2. В Routekeeper откройте «Прокси» и нажмите ⌘V или кнопку «Вставить» под списком. Откроется новый прокси с заполненными полями.
  3. «DNS через прокси» и «Блокировать UDP и QUIC» уже включены — оставьте их и нажмите «Добавить».
  4. «Проверить» должен показать IP вашего сервера.
  5. В «Правилах» отправьте нужные приложения через этот прокси.
Строка — это ключ от прокси: не публикуйте её и не пересылайте в чаты. Увидеть её снова можно, запустив команду установки ещё раз, а логин и пароль лежат на сервере в /etc/caddy/proxy-credentials.

Защита сервера

Боты круглосуточно подбирают пароли root: на нашем тестовом сервере набиралось около 11 тысяч попыток в сутки. fail2ban блокирует каждый такой адрес после пяти ошибок, но надёжнее совсем отключить вход по паролю и входить по ключу. На Mac:

ssh-keygen -t ed25519 -f ~/.ssh/my_server
ssh-copy-id -i ~/.ssh/my_server.pub root@IP
ssh -i ~/.ssh/my_server root@IP

Если последняя команда пустила на сервер без пароля root, в этой же сессии отключите пароли:

printf 'PasswordAuthentication no\nPermitRootLogin prohibit-password\n' > /etc/ssh/sshd_config.d/10-keys-only.conf
systemctl reload ssh
Не закрывайте эту сессию, пока не проверите вход по ключу в новом окне Терминала. Если сервером управляют другие приложения по паролю root (например, клиент Amnezia), им после этого тоже понадобится ключ.

Если не получилось

  • «A-запись … должна указывать на …» — домен ещё не обновился или указывает не туда. Проверьте IP в DuckDNS, подождите пару минут и запустите команду снова.
  • «Порты 80 и 443 заняты» — на сервере уже работает сайт или VPN-панель. Возьмите отдельный сервер.
  • «Caddy не получил сертификат» — чаще всего порты 80 и 443 закрыты в панели хостера (firewall, security group). Откройте их и запустите команду снова. Если переустанавливали много раз за неделю, Let's Encrypt может временно отказывать этому домену: возьмите другое имя на DuckDNS.
  • «Нужен сервер x86_64» — серверы на ARM пока не поддерживаются.
  • Routekeeper не проверяет прокси — в поле «Сервер» должен быть домен, а не IP, и строка должна быть вставлена целиком.
  • Медленно — выберите сервер ближе. На маршруте с пингом около 200 мс одно соединение даёт примерно 3–4 МБ/с.
  • Прокси работал, а потом перестал — в некоторых сетях TLS-прокси распознают по характеру трафика. Запасной путь — sing-box или Xray на том же сервере и их локальный SOCKS5 на Mac, см. «Свой прокси». Правила в Routekeeper менять не придётся.

Если застряли, откройте issue на GitHub и приложите вывод скрипта. Строку прокси и пароль из него удалите.
