Приложения и сервисы: кто идёт через прокси

В разделе «Приложения» задаётся маршрут целого приложения или целого сервиса. Одна строка — один выбор: через прокси, напрямую, блокировать или спрашивать.

В разделе Приложения (⌘2) строки двух видов. Строка приложения задаёт, куда идёт весь его трафик. Строка сервиса задаёт, куда идут адреса одного сайта или мессенджера из всех приложений сразу.

Исключения по адресам, портам и протоколам, например «браузер через прокси, но сайты компании напрямую», задаются в разделе Правила. Как маршруты, сервисы и правила складываются вместе, рассказано в разделе Как это работает.

Как добавить приложение

  1. Откройте раздел Приложения.
  2. Нажмите кнопку + (Добавить) на панели инструментов: на ней только значок, название видно в подсказке. Откроется окно Установленные приложения: приложения из папок «Программы» и «Утилиты», системные и из папки «Программы» в вашей домашней папке.
  3. Найдите нужные приложения поиском, выберите одно или несколько и нажмите Добавить.

Другие способы добавить приложение:

  • Перетащить приложение из Finder или из Dock прямо в список.
  • Меню кнопки Добавить (стрелка рядом с ней):
    • Из списка установленных… — то же окно, что по щелчку;
    • Выбрать файл… — окно выбора файла: приложение или программа из любой папки;
    • Указать путь… — вписать путь к программе, удобно для программ командной строки;
    • Сервис и Все сервисы… — сервисы.
  • Из любого раздела: ⇧⌘N открывает список установленных приложений.
  • При первом запуске: кнопка Выбрать приложения… на приветственном экране.

Новое приложение получает маршрут через основной прокси. Если прокси ещё нет, маршрут — Напрямую. Поменять его можно в меню маршрута, см. ниже. Если приложение уже есть в списке, Routekeeper выделит его строку, а не добавит вторую.

Как Routekeeper узнаёт приложение

Routekeeper узнаёт приложение по подписи кода: по идентификатору разработчика и идентификатору приложения. Поэтому маршрут сохраняется после обновления приложения и после его переноса в другую папку. Другая программа с тем же названием под маршрут не попадёт.

Программы без подписи разработчика Routekeeper узнаёт по пути к файлу. Если такую программу переместить или переименовать, её нужно добавить заново. Так часто бывает с программами командной строки, например из Homebrew, см. ниже.

Подробнее: ключ приложения
  • Программы Apple и приложения из App Store — по идентификатору подписи, например com.apple.Safari.
  • Приложения с подписью Developer ID — по идентификатору подписи вместе с Team ID разработчика.
  • Программы с подписью ad-hoc и без подписи — по полному пути к исполняемому файлу.

Под названием приложения в строке написан этот идентификатор или путь, а также «+ дочерние процессы», если они включены.

Маршрут приложения

Справа в строке — меню маршрута. На нём написан текущий маршрут, например «Прокси: Амстердам» или «Напрямую». Щёлкните, чтобы выбрать другой:

МаршрутЧто происходит
Через прокси → название проксиВсе соединения приложения идут через выбранный прокси. Его UDP блокируется, если у прокси включён переключатель Блокировать UDP и QUIC.
НапрямуюСоединения идут так, как без Routekeeper.
БлокироватьСоединения приложения блокируются.
СпрашиватьНа каждое новое назначение Routekeeper показывает окно вопроса, см. Спрашивать.

Подробнее о действиях — в разделе Как это работает.

Строки собраны в группы по маршруту: Через прокси, Блокируются, Спрашивать, Напрямую. Над ними раздел Сервисы. Если приложение сейчас передаёт данные через прокси, в его строке видна скорость «↕ …».

Внизу свёрнута группа Разрешены автоматически с числом строк. В ней программы Apple и приложения, установленные до Routekeeper, которым режим Спрашивать разрешил выход в сеть без вопроса. Если выбрать такому приложению маршрут, оно перейдёт в обычную группу.

Включить, выключить, удалить

  • Переключатель справа выключает строку, не удаляя её. Выключенная строка не действует: приложение идёт по остальным правилам и по режиму. В режиме Только прокси это значит напрямую.
  • Контекстное меню (щелчок правой кнопкой): Маршрут, Включить или Выключить, Вместе с дочерними процессами, Показать в Finder, Удалить. Маршрут, включение и удаление работают и для нескольких выделенных строк сразу.
  • Удалить можно и клавишей Delete. Последнее изменение отменяет ⌘Z.
  • Поиск на панели инструментов ищет по названию и идентификатору приложения, а сервисы — ещё и по домену: googlevideo.com найдёт YouTube.

Приложение, которого нет в списке, идёт по режиму. В режиме Только прокси — напрямую.

Строка приложения задаёт, куда идёт весь его трафик. Каждая такая строка — это правило, его видно и в разделе Правила с назначением «Любой адрес». Чтобы часть адресов приложения шла иначе, добавьте правило: Когда нужно правило.

Подробнее: какие правила показаны в «Приложениях»

Здесь показаны постоянные правила с конкретным приложением, любым адресом, без порта и протокола. Ответ в окне вопроса со сроком Навсегда и назначением Куда угодно тоже становится такой строкой. Временные правила со сроком «Пока работает…», правила для отдельных адресов и встроенные правила видны только в разделе Правила.

Дочерние процессы

Многие приложения выходят в сеть не сами, а через вспомогательные программы — дочерние процессы. У браузеров и приложений вроде Slack или VS Code сетью занимаются процессы-помощники вроде «Google Chrome Helper». Терминал запускает git, curl, npm, ssh.

Настройка Вместе с дочерними процессами распространяет маршрут приложения на:

  • программы-помощники внутри самого приложения от того же разработчика;
  • программы, которые приложение запустило, в том числе через промежуточные: Терминал → оболочка → git.

Настройка включена по умолчанию у каждого нового приложения. Например, если у Терминала маршрут Через прокси, через прокси идёт всё, что вы в нём запускаете: git, curl, npm, brew.

Выключить настройку можно в контекстном меню строки: снимите отметку Вместе с дочерними процессами. Тогда маршрут действует только на основной процесс приложения. Делайте это осознанно: браузеры и многие другие приложения выходят в сеть только через помощников, и без этой настройки маршрут может не поймать ничего.

Собственная строка запущенной программы важнее строки приложения, которое её запустило. Если у Терминала маршрут Через прокси, а у curl своя строка Напрямую, то curl, запущенный из Терминала, пойдёт напрямую. Почему так, объяснено в разделе Правила.

Подробнее: что считается дочерним процессом

При включённой настройке процесс относится к приложению, если выполняется хотя бы одно:

  • процесс находится внутри пакета приложения (…/Slack.app/…) и подписан тем же Team ID;
  • идентификатор подписи процесса начинается с идентификатора приложения и точки, а Team ID тот же: com.google.Chrome.helper для com.google.Chrome;
  • среди его предков — само приложение или процесс из пакета приложения. Предки ищутся по «ответственному» процессу macOS, затем по родителю, до восьми уровней вверх.

Если помощник приложения, которое идёт через прокси, ни под одно из этих условий не попал и вышел в сеть напрямую, раздел Мимо прокси (в версии 0.2.1 — Утечки) отметит это как Процесс мимо правила.

Программы командной строки

git, curl, npm, python3, ssh — отдельные программы, их нет в списке установленных приложений. Направить их можно двумя способами.

Через терминал целиком

Самый простой и надёжный способ. Добавьте приложение, из которого вы запускаете команды: Терминал, iTerm или редактор кода со встроенным терминалом. Выберите ему маршрут. С включённой настройкой Вместе с дочерними процессами всё, что вы запускаете в нём, пойдёт тем же маршрутом. Готовый сценарий — в рецепте Терминал, инструменты разработчика и AI-приложения.

Отдельная программа по пути

  1. В разделе Приложения откройте меню кнопки Добавить и выберите Указать путь….
  2. Впишите полный путь к программе, например /usr/bin/curl. Можно начинать путь с ~ для домашней папки.
  3. Нажмите Добавить. Появится строка с именем программы и маршрутом по умолчанию.

Ещё можно выбрать файл через Выбрать файл…. Скрытые папки вроде /usr/bin в окне выбора открываются сочетанием ⇧⌘G: впишите путь к папке и нажмите Return.

Программы Apple, например /usr/bin/curl и /usr/bin/ssh, Routekeeper узнаёт по подписи Apple. С большинством остальных сложнее: у программ из Homebrew и многих других нет подписи разработчика, и Routekeeper узнаёт их по пути к файлу.

Программы Homebrew. В /opt/homebrew/bin лежат не сами программы, а ссылки на них в папке с номером версии. Routekeeper видит запущенную программу по настоящему пути, поэтому указывайте его, а не путь к ссылке. Настоящий путь печатает эта команда (вместо git подставьте свою программу):

readlink -f "$(which git)"

После обновления программы через brew upgrade путь меняется, и строку нужно добавить заново. Поэтому для таких программ проще направлять терминал целиком.

Подробнее: скрипты и общие программы Apple
  • Скрипты на Python, Node.js и других языках выходят в сеть от имени интерпретатора: python3, node. Строка нужна для интерпретатора или для терминала.
  • Часть программ в /usr/bin — git, python3, make и другие инструменты разработчика — общие «прокладки» Apple с одной и той же подписью. Строка для /usr/bin/git подействует на все такие программы и на то, что они запускают.
  • Найти, где лежит программа, помогает команда which, например which curl.

Сервисы

Сервис — готовый набор адресов одного известного сайта или мессенджера: домены со всеми поддоменами, а иногда и подсети. Строка сервиса действует во всех приложениях сразу: в браузерах, в настольных клиентах и в программах командной строки.

Например, сервис YouTube с маршрутом Через прокси: любое приложение, которое обращается к youtube.com или googlevideo.com, идёт через прокси. Остальной трафик браузера идёт по маршруту самого браузера.

Как добавить сервис

  • Кнопки популярных сервисов в разделе Сервисы вверху списка добавляют сервис одним щелчком.
  • Меню кнопки Добавить → Сервис — все сервисы по группам.
  • Все сервисы… — окно с поиском по названию или домену: openai.com найдёт ChatGPT. Выберите один или несколько и нажмите Добавить.
  • При первом запуске — кнопки сервисов на шаге Что пустить через прокси приветственного экрана.

Новый сервис получает маршрут через основной прокси, а если прокси нет — Напрямую. В меню маршрута сервиса есть прокси, Напрямую и Блокировать. Варианта Спрашивать у сервиса нет.

Какие сервисы есть

32 сервиса в четырёх группах (в версии 0.2.1 — 25, без TikTok, Reddit, Twitch, Slack, Zoom, GitHub и Figma):

  • Популярные — например, YouTube, Telegram, GitHub, Slack, Zoom, Notion, Figma, JetBrains, Spotify.
  • Meta — Instagram, Facebook, WhatsApp, Threads.
  • AI-ассистенты — например, ChatGPT, Claude, Gemini, GitHub Copilot, Cursor.
  • Российские сервисы — Госуслуги и госсайты, Российские банки, Российские сайты.

Полный список — в окне Все сервисы…. Сервисы группы Российские сервисы добавляются с маршрутом Напрямую. Их удобно добавить, если браузер целиком идёт через прокси, а эти сайты нужно открывать с вашего обычного адреса.

Нужного сервиса нет — добавьте правило с доменами сайта в разделе Правила.

Сервис важнее маршрута приложения

Строка сервиса действует на любое приложение и для адресов сервиса важнее маршрута самого приложения:

  • Браузер идёт Через прокси, сервис «Российские банки» — Напрямую. Сайты банков открываются напрямую, всё остальное — через прокси.
  • Браузера нет в списке или у него маршрут Напрямую, сервис GitHub — Через прокси. Через прокси идёт только GitHub.

Но и сервис можно перебить. Ваше правило для конкретного домена из его списка важнее сервиса. Важнее и правило для этого же сервиса с конкретным приложением, портом или протоколом. Точный порядок — в разделе Правила.

Сервису нужно имя сайта. Соединения на голый IP-адрес и большая часть UDP, включая QUIC в браузерах, имени не несут и идут по маршруту приложения. Если сервис идёт через прокси, а браузер — напрямую, видео может пойти мимо прокси по QUIC. Решение — правило «браузер · порт 443 · UDP → Блокировать»: как его сделать. В некоторых сервисах есть и подсети, например у Telegram: такие соединения сервис узнаёт и по IP.

Приложения сервиса добавляются сами

Вместе с некоторыми сервисами Routekeeper добавляет строки для их настольных приложений и программ командной строки, с тем же маршрутом, что у сервиса. Например:

  • Slack — приложение Slack;
  • Zoom — приложение zoom.us;
  • JetBrains — IntelliJ IDEA, PyCharm и другие среды разработки JetBrains;
  • Claude — приложение Claude и программа claude для терминала.

Зачем: настольные приложения иногда подключаются по IP или к адресам, которых нет в списке сервиса. Маршрут целого приложения ловит всё.

  • Приложения, установленные позже. Routekeeper следит за включёнными сервисами. Когда вы установите и запустите приложение такого сервиса, его строка появится сама.
  • Ваши строки не меняются. Если приложение уже есть в списке с выбранным вами маршрутом, он останется. Строка из группы Разрешены автоматически получит маршрут сервиса.
  • Потом это отдельные строки. Если поменять маршрут сервиса или удалить сервис, строки его приложений останутся как были. Меняйте их отдельно.

В версии 0.2.1 приложения сервисов автоматически не добавляются.

Карточка сервиса

Кнопка ⓘ в строке сервиса открывает его карточку. Её же открывают двойной щелчок по строке и пункт Подробнее… в контекстном меню. В карточке:

  • вверху — название, число адресов в наборе и переключатель; группа подписана только у наборов из групп Meta, AI-ассистенты и Российские сервисы;
  • Что делает правило — меню Маршрут, правило словами и оговорки. Например, у мессенджеров: «Звонки идут по UDP и через прокси не работают». Ниже — Важнее этого правила: ваши правила, которые забирают часть трафика сервиса раньше него;
  • Что попало под правило — приложения и адреса из последних соединений в Мониторе, которые решил этот сервис;
  • Что входит — все имена и подсети набора. В поле Проверить адрес или найти в списке впишите имя, например i.ytimg.com, и карточка скажет, входит ли оно в сервис. Ответ появляется, когда в тексте есть точка, а список ниже показывает только записи, содержащие введённый текст, поэтому для поддомена он может опустеть — смотрите на строку с ответом;
  • кнопки Удалить сервис и Готово.

Обновление сервисов

Список сервисов, их адреса и приложения, которые добавляются вместе с ними, Routekeeper берёт из каталога сервисов. Адреса в нём — из открытого проекта v2fly/domain-list-community, подсети Telegram — из списка, который публикует Telegram.

Раз в 6 часов Routekeeper проверяет на getroutekeeper.app, нет ли каталога новее, и ставит его без обновления приложения. Так появляются новые сервисы, меняются адреса и добавляются новые приложения сервисов. Файл каталога подписан, сетевое расширение проверяет подпись. Если проверка не удалась, например нет сети, Routekeeper повторит её в течение часа.

Дата каталога и ручная проверка: Настройки → Основные → Каталог сервисов (в версии 0.2.1 — Адреса сервисов), строки Списки от и Последняя проверка и кнопка Проверить списки. Что Routekeeper при этом отправляет в сеть, описано на странице Конфиденциальность.
