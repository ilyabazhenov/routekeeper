Прокси: куда отправлять трафик

Прокси — сервер, через который Routekeeper отправляет трафик выбранных приложений. Здесь всё о том, как его добавить, проверить и при необходимости заменить другим.

У Routekeeper нет своих серверов. Трафик приложений он отправляет на прокси, который укажете вы: свой сервер, клиент другой программы на этом Mac, рабочий прокси или прокси от провайдера.

Приложение → Routekeeper → прокси → сайт

Своего прокси нет? Routekeeper поставит его на арендованный сервер сам: нужны только IP и пароль от сервера. Как — в разделе Свой прокси-сервер.

Какой тип выбрать

Routekeeper работает с прокси трёх типов. Тип определяет, как Routekeeper договаривается с сервером. Приложения разницы не замечают.

ТипПорт по умолчаниюКогда выбиратьЧто важно знать
SOCKS51080Клиент sing-box, Xray или Clash на этом Mac. Прокси от провайдера со строкой вида socks5://….Соединение с прокси не шифруется: логин, пароль и имена сайтов видны по пути.
HTTP8080Рабочий прокси в офисе. Прокси со строкой вида http://….Соединение с прокси не шифруется. Вход только по логину и паролю.
HTTPS443Свой сервер, поднятый по инструкции. Прокси со строкой вида https://….Соединение с прокси зашифровано TLS. В поле Сервер нужно доменное имя.

Как выбрать:

  • Есть строка прокси от провайдера или из скрипта установки сервера — просто вставьте её, тип определится сам.
  • Свой сервер по нашей инструкции — HTTPS.
  • Клиент на этом Mac — SOCKS5, сервер 127.0.0.1. Подробнее — в разделе Локальный клиент.
  • Прокси на работе — HTTP, или HTTPS, если так сказали в IT-отделе. Подробнее — в разделе Рабочий прокси.
  • Удалённый сервер и выбор есть — берите HTTPS. Через SOCKS5 и HTTP по интернету тоже работает, но логин, пароль и имена сайтов идут открытым текстом. Содержимое сайтов по HTTPS остаётся зашифрованным в любом случае.

Другие протоколы, например Shadowsocks или VLESS, Routekeeper напрямую не поддерживает. Если ваш сервер работает по такому протоколу, запустите на Mac его клиент и подключите Routekeeper к локальному порту клиента, как описано ниже.

Подробнее: как Routekeeper говорит с прокси каждого типа
  • SOCKS5 — по RFC 1928, вход по логину и паролю — по RFC 1929. Используется только команда CONNECT, то есть только TCP. UDP ASSOCIATE Routekeeper не использует, поэтому UDP через SOCKS5 не идёт, даже если клиент его умеет.
  • HTTP — для каждого соединения открывается туннель методом CONNECT, в том числе к порту 80. Логин и пароль передаются в заголовке Proxy-Authorization: Basic.
  • HTTPS — тот же CONNECT внутри TLS 1.2 или новее, ALPN http/1.1. Сертификат сервера проверяется по доверенным корневым сертификатам macOS и по имени из поля Сервер. Самоподписанный сертификат не пройдёт проверку.
  • На установку туннеля (TCP, TLS и договорённость с прокси) отводится 15 секунд, при проверке — 10 секунд. Открытые туннели проверяются TCP keepalive: после 30 секунд тишины три пробы раз в 10 секунд. Туннель, у которого пропал сервер, закрывается примерно через минуту.

Как добавить прокси

Быстрее всего — вставить строку прокси. Если строки нет, заполните поля вручную.

  1. В окне Routekeeper откройте раздел Прокси (⌘4).
  2. Нажмите + под списком прокси или кнопку + (Добавить прокси) на панели инструментов — там только значок. Из любого раздела то же делает ⌥⌘N. Справа откроются пустые поля.
  3. Заполните поля по таблице ниже. Если прокси ещё нет, а есть арендованный сервер, вместо этого нажмите Свой сервер… на панели инструментов (значок сервера): Routekeeper поставит прокси на сервер и добавит его сам, см. Свой прокси-сервер.
  4. Нажмите Проверить. Проверять можно до сохранения: Routekeeper возьмёт то, что вписано в поля. Что означает результат, написано в разделе Проверка.
  5. Нажмите Добавить. Прокси появится в списке слева, и Routekeeper сразу проверит его ещё раз.

При первом запуске то же самое есть на приветственном экране: шаг Добавить прокси-сервер, кнопки Вставить из буфера и Ввести вручную….

ПолеЧто вписать
НазваниеЛюбое имя, которое вы увидите в меню маршрутов: «Амстердам», «Офис». Если оставить поле пустым, названием станет адрес сервера.
ТипSOCKS5, HTTP или HTTPS. Как выбрать — выше.
СерверДоменное имя вроде proxy.example.net или IP-адрес вроде 203.0.113.10; IPv6 тоже можно. Без https:// и без порта. Для HTTPS — только доменное имя: по нему проверяется сертификат.
ПортПорт прокси, число от 1 до 65535. Если оставить поле пустым, Routekeeper возьмёт порт по умолчанию для типа: 1080, 8080 или 443. Подсказка в поле показывает, какой именно.
ЛогинЕсли прокси пускает без пароля, оставьте пустым.
ПарольСохраняется только вместе с логином.
DNS через проксиВключено по умолчанию, обычно не трогайте. Что делает — в разделе ниже.
Блокировать UDP и QUICВключено по умолчанию, обычно не трогайте.

Чтобы изменить прокси, выберите его в списке, поправьте поля и нажмите Сохранить. Отменить изменения возвращает сохранённые значения. Строка Используется в правилах: N под кнопкой Проверить показывает, сколько маршрутов и правил идут через этот прокси.

Подробнее: где хранится пароль

Пароль хранит сетевое расширение Routekeeper в своём файле настроек. Этот файл может прочитать только система (root). Окно Routekeeper сохранённый пароль не получает: в поле Пароль вместо него точки, а проверку прокси выполняет само расширение. Если поле не трогать, при сохранении пароль остаётся прежним. Если очистить Логин, пароль удалится.

Вставить строку прокси

Провайдеры и скрипт установки сервера выдают прокси одной строкой. Routekeeper разбирает её сам.

  1. Скопируйте строку прокси (⌘C).
  2. Вставьте её в Routekeeper:
    • Раздел Прокси: щёлкните по списку прокси слева и нажмите ⌘V или нажмите Вставить под списком.
    • Приветственный экран: на шаге Добавить прокси-сервер нажмите Вставить из буфера.
  3. Откроется новый прокси с заполненными полями. Проверьте тип, сервер, порт и логин, нажмите Проверить, затем Добавить. Пока вы не нажали Добавить, ничего не сохраняется.

Какие строки понимает Routekeeper:

СтрокаТипЛогин и пароль
socks5://user:pass@203.0.113.10:1080SOCKS5user и pass
socks5h://203.0.113.10:1080, socks://203.0.113.10:1080SOCKS5нет
http://proxy.corp.example:3128HTTPнет
https://user:pass@proxy.example.net:443HTTPSuser и pass
203.0.113.10:1080SOCKS5нет
203.0.113.10:1080:user:passSOCKS5user и pass
user:pass@203.0.113.10:1080SOCKS5user и pass
socks5://[2001:db8::1]:1080SOCKS5, адрес IPv6 в квадратных скобкахнет
  • Порт обязателен, даже в строке https://. Строка https://proxy.example.net без :443 не распознается.
  • Без приставки (socks5://, http://, https://) получится SOCKS5. Если провайдер дал строку адрес:порт для HTTP-прокси, после вставки смените Тип на HTTP.
  • Особые символы в логине и пароле можно записать в виде %40 вместо @ или %3A вместо :. Routekeeper раскодирует их.
  • Пробелы и переносы строк по краям и косая черта в конце не мешают.
  • Название вставленного прокси — адрес сервера. Его можно поменять в поле Название.

Если в буфере обмена не строка прокси, Routekeeper ответит: «В буфере обмена нет строки прокси. Ожидается, например, socks5://user:pass@host:1080». Пункт Скопировать адрес в контекстном меню прокси копирует обратно только адрес:порт, без логина и пароля.

Подробнее: socks5 и socks5h

В других программах буква h в socks5h:// значит «имена сайтов узнаёт прокси». В Routekeeper обе приставки дают одинаковый SOCKS5. Будет ли прокси получать имена, решает переключатель DNS через прокси, и у вставленного прокси он включён.

DNS через прокси и блокировка UDP

У каждого прокси два переключателя: DNS через прокси и Блокировать UDP и QUIC. Оба включены по умолчанию, в том числе у вставленного прокси. Они действуют на соединения, которые идут через этот прокси.

DNS через прокси

Когда приложение открывает сайт по имени, Routekeeper передаёт прокси имя, например example.com, а не IP-адрес, который нашёл ваш Mac. Адрес сайта прокси узнаёт сам, через свой DNS.

Так сайт открывается по адресу, который подходит для местоположения сервера: крупные сайты отдают разные адреса в разных странах. И если DNS вашей сети ответил неверным адресом, прокси всё равно найдёт правильный.

Работает это, только когда имя известно. Если приложение само подключается к IP-адресу, прокси получает IP. Подробнее о соединениях без имени — в разделе Правила.

Когда выключать. Если нужные имена знает только DNS вашей локальной или рабочей сети, а прокси находится за её пределами. Например, внутренние сайты компании, которые открываются только из офисной сети: удалённый прокси их не найдёт. С выключенным переключателем Routekeeper передаёт прокси адрес, который нашёл ваш Mac. В остальных случаях держите переключатель включённым.

Подробнее: что видит DNS вашей сети

Соединение попадает в Routekeeper, когда приложение уже знает адрес сервера. Если имя узнавала сама macOS, её запрос ушёл в DNS вашей сети раньше, чем Routekeeper увидел соединение. Переключатель решает, по какому адресу прокси откроет сайт, но этот запрос не отменяет. Как устроен DNS в Routekeeper и как браузер может узнавать имена по защищённому каналу, рассказано в разделах Как это работает и DNS через HTTPS в браузере.

Блокировать UDP и QUIC

SOCKS5, HTTP и HTTPS-прокси передают только TCP. UDP — другой вид трафика: на нём работают QUIC в браузерах, голосовые и видеозвонки, игры. Через прокси UDP пройти не может.

  • Переключатель включён (по умолчанию). UDP-соединения приложений, которые идут через этот прокси, блокируются. Браузеры в ответ переходят на обычный HTTPS по TCP, и он идёт через прокси. Сайты открываются как обычно.
  • Переключатель выключен. UDP этих приложений уходит напрямую, мимо прокси, с вашим настоящим IP. Каждое такое соединение отмечается в разделе Мимо прокси (в версии 0.2.1 — Утечки) как UDP мимо прокси.

DNS-запросы (порты 53 и 853) переключатель не блокирует: без них приложения перестали бы работать. Такие запросы идут напрямую и отмечаются в Мимо прокси как DNS мимо прокси.

Когда выключать. Когда важнее, чтобы работали звонки, чем чтобы они шли через прокси. Например, мессенджер идёт через прокси, а звонки в нём используют UDP: с блокировкой они не соединятся вовсе, без неё пойдут напрямую. Переключатель действует на все приложения этого прокси. Чтобы не трогать остальные, добавьте тот же сервер ещё раз под другим названием, выключите блокировку только у этой копии и выберите её маршрутом для мессенджера. Через прокси звонки по UDP не работают в любом случае, см. Ограничения.

Подробнее: когда срабатывает переключатель

Переключатель проверяется для UDP-соединения, которое по правилам должно идти через этот прокси: по маршруту приложения, по сервису или по правилу. Соединения на порты 53 и 853 пропускаются напрямую с отметкой «DNS мимо прокси», если раньше их не заблокировало отдельное правило. Остальной UDP блокируется или, при выключенном переключателе, пропускается напрямую с отметкой. UDP приложений, которые через прокси не идут, переключатель не касается. Например, QUIC браузера без имени сайта идёт по маршруту самого браузера, см. Правила по именам сайтов.

Проверка

Кнопка Проверить открывает через прокси соединение со службой ipinfo.io и спрашивает, какой IP-адрес она видит. Через пару секунд рядом появится результат, например:

Работает · 640 мс · IP 203.0.113.10 (NL)
  • IP — адрес, который видят сайты. Если он совпадает с адресом вашего сервера, прокси работает.
  • Код страны в скобках — где этот адрес зарегистрирован по данным ipinfo.io.
  • Миллисекунды — время, за которое открывается новое соединение через прокси. Это несколько обменов с сервером, поэтому далёкий исправный сервер показывает 500–800 мс. В Обзоре время от 1500 мс помечается словом «медленно».

В списке прокси слева у каждого прокси цветная точка и короткая строка: зелёная — работает (SOCKS5 · 640 мс · NL), красная — недоступен, синяя — проверяем…, серая — не проверен.

Нажимать Проверить каждый раз не нужно. Routekeeper проверяет прокси сам: после сохранения; при открытии раздела Прокси, если прокси ещё не проверялся; при открытии меню значка в строке меню и после смены сети — основной прокси. Пока основной прокси не отвечает, он перепроверяется раз в минуту. Проверить все прокси сразу — кнопка Проверить все на панели инструментов.

Прокси на своём сервере

Прокси, который Routekeeper поставил мастером Свой сервер…, получает внизу карточки блок Сервер. Routekeeper входит на сервер по своему ключу из связки ключей, делает одно действие и выходит.

КнопкаЧто делает
Проверить серверУзнаёт, работает ли прокси на сервере, до какого числа действует сертификат и сколько адресов не пускает fail2ban. Сертификат Caddy продлевает сам, за месяц до срока.
Переустановить или Обновить серверЗапускает установку ещё раз с тем же доменом. Так чинят остановленный прокси и обновляют Caddy и настройки до версии из этого Routekeeper. Логин и пароль не меняются.
Ещё → Сменить пароль прокси…Создаёт на сервере новые логин и пароль и сразу сохраняет их в этом прокси. Маршруты и правила остаются на нём. Если этот прокси настроен ещё где-то, там старый пароль перестанет подходить.
Ещё → Закрыть вход на сервер по паролю…Сервер начинает пускать по SSH только по ключу. Подробнее — в разделе Вход на сервер по паролю.
Ещё → Сохранить ключ SSH…Сохраняет в файл закрытый ключ, которым Routekeeper входит на сервер. С ним можно войти на сервер из Терминала: ssh -i файл root@IP.
Ещё → Удалить прокси с сервера…Удаляет на сервере Caddy, сертификат, логин и пароль. Сервер и остальное на нём остаются. В диалоге можно удалить прокси и в Routekeeper или оставить его.
Ещё → Забыть сервер…Routekeeper удаляет ключ этого сервера и перестаёт им управлять. Прокси на сервере и в Routekeeper продолжает работать, блок Сервер исчезает.

Если блок показывает ошибку, ссылка Что с этим делать под ней ведёт в нужный раздел страницы Свой прокси-сервер.

Если вход на сервер по паролю закрыт, ключ Routekeeper может быть единственным, с которым сервер пускает. Забыть сервер… и удаление прокси удаляют этот ключ из связки ключей, поэтому сначала сохраните его: Ещё → Сохранить ключ SSH….

Несколько прокси

Прокси можно добавить сколько угодно. Каждое приложение, сервис и правило выбирает свой: в меню маршрута есть раздел Через прокси со всеми прокси по названию. Например, браузер идёт через «Амстердам», а рабочий мессенджер — через «Офис». Как выбрать маршрут, описано в разделе Приложения.

Если у двух прокси одинаковые названия, в меню к ним добавляются тип и порт. Понятнее дать им разные названия.

Основной прокси

Основной — прокси, через который идёт больше всего включённых маршрутов и правил. Если таких нет, основным считается первый в списке. Основной прокси:

  • показан в панели внизу боковой колонки окна, со временем отклика и страной, и в меню значка в строке меню, с внешним IP и страной;
  • становится маршрутом новых приложений и сервисов;
  • предлагается в быстрых действиях Монитора.

Число вида «+1» рядом с ним в боковой колонке значит, что часть правил идёт через другие прокси.

Удаление прокси

Выберите прокси в списке и нажмите − под списком или клавишу Delete. Ещё можно щёлкнуть по прокси правой кнопкой и выбрать Удалить…. Routekeeper спросит подтверждение и скажет, сколько правил идёт через этот прокси. Удаление отменить нельзя: ⌘Z его не вернёт, логин и пароль удаляются вместе с прокси.

Маршруты и правила, которые шли через удалённый прокси, выключаются.

Если прокси поставил мастер Свой сервер…, в диалоге две кнопки: Удалить и с сервера снимает прокси с сервера и затем удаляет его в Routekeeper, Удалить только из Routekeeper оставляет прокси на сервере работать, а Routekeeper забывает сервер и его ключ.

Выключенное правило не действует. Приложения, которые шли через удалённый прокси, пойдут по остальным правилам и по режиму. В режиме Только прокси это значит напрямую, с вашим настоящим IP, и в Мимо прокси такие соединения не попадут. Поэтому сначала переведите маршруты на другой прокси, а потом удаляйте.

Перевод на другой прокси

Когда прокси перестал работать или вы переезжаете на другой сервер, маршруты можно перевести разом, не меняя каждое приложение. Для этого нужно хотя бы два прокси.

ГдеЧто переводится
Обзор → Маршруты → кнопка ⋯ в строке прокси → Перевести маршруты наТолько маршруты и правила этого прокси.
Обзор → строка прокси, который не отвечает → Перевести на «…»Только маршруты и правила этого прокси. Routekeeper предлагает прокси, который ответил при последней проверке.
Панель внизу боковой колонки → строка Прокси → Перевести все приложения наВсе включённые маршруты и правила, которые идут через любой прокси.
Меню значка в строке меню → Прокси для всех приложенийТо же, что в боковой колонке. Список появляется в меню, только когда прокси два или больше.
  1. Выберите прокси, на который переводить.
  2. Routekeeper спросит: Перевести на «…»? В вопросе написано, что переедет и откуда. Если правила шли через разные прокси, Routekeeper предупредит, что разделение пропадёт. Если выбранный прокси не ответил при последней проверке, тоже предупредит. Нажмите Перевести. В меню строки меню вопрос появляется прямо в меню.
  3. После перевода на 10 секунд появится строка вида «5 правил переведено» и кнопка Отменить: она вернёт переведённые правила на прежние прокси. Позже то же делает ⌘Z в окне Routekeeper.

Переводятся только включённые маршруты и правила с действием Через прокси. Напрямую, Блокировать и выключенные правила остаются как были. Уже открытые соединения остаются на прежнем прокси, пока приложение не переподключится.

Если прокси недоступен

По умолчанию соединения, которые должны идти через прокси, при его отказе обрываются. Приложение покажет ошибку или «нет сети», но напрямую соединения не уходят, и ваш настоящий IP не раскрывается.

Что вы увидите:

  • в Обзоре — заголовок «Прокси «…» недоступен», а если другие прокси с маршрутами работают — «Работает частично»;
  • в Маршрутах строка прокси станет оранжевой: «Не отвечает» и «Что идёт через этот прокси, сейчас не соединяется. Напрямую оно не уходит.», рядом кнопки Перевести на «…» и Проверить снова;
  • в меню значка в строке меню — оранжевая строка «Прокси «…» недоступен», если отказал основной прокси.

Что делать: перевести маршруты на другой прокси, как описано выше, или подождать. Основной прокси перепроверяется раз в минуту. Как только сервер ответит, новые соединения снова пойдут через него.

Если вам важнее, чтобы приложения работали, чем чтобы они шли через прокси, включите Настройки → Сеть → Если прокси недоступен — пускать напрямую. По умолчанию это выключено. С этой настройкой соединение, которое не удалось провести через прокси, идёт напрямую: сайты видят ваш настоящий IP. Монитор покажет такие соединения как прямые, а в Мимо прокси они не попадут. Готовый сценарий — в рецепте Прокси перестал отвечать.

Подробнее: как отказ выглядит для приложения

Routekeeper принимает соединение приложения сразу и одновременно подключается к прокси. Так браузеры не открывают лишних запасных соединений. Если прокси отказал или не ответил за 15 секунд, соединение приложения обрывается. С настройкой «пускать напрямую» Routekeeper в этот момент подключается к адресу сайта сам. Блокировка UDP от состояния прокси не зависит.

Локальный клиент: sing-box, Xray, Clash

Если вы уже пользуетесь клиентом вроде sing-box, Xray, Clash или программой на их основе, Routekeeper может отправлять в него выбранные приложения. Клиент по-прежнему держит связь с вашим сервером по своему протоколу, а Routekeeper решает, какие приложения в него идут.

Приложение → Routekeeper → SOCKS5 127.0.0.1 → клиент → ваш сервер → сайт
  1. В настройках клиента найдите порт локального прокси. Он может называться SOCKS port, mixed port или inbound, например 1080 или 7890.
  2. В клиенте выключите системный прокси (System Proxy, Set as system proxy) и режим TUN (TUN mode, Enhanced mode, VPN mode). С системным прокси приложения сами идут в клиент, и Routekeeper ими уже не управляет. TUN перехватывает весь трафик Mac, как VPN, и мешает Routekeeper, см. Ограничения.
  3. В Routekeeper добавьте прокси: Тип SOCKS5, Сервер 127.0.0.1, Порт — порт клиента. Логин и пароль обычно не нужны. Можно скопировать и вставить строку socks5://127.0.0.1:7890, подставив свой порт.
  4. Оба переключателя оставьте включёнными. С DNS через прокси клиент получает имена сайтов и узнаёт адреса по своим настройкам.
  5. Нажмите Проверить. IP в ответе должен быть адресом вашего сервера, а не вашим домашним.
  6. Выберите приложения, которые пойдут через клиент: Приложения и сервисы.

Не отправляйте сам клиент через прокси. Его соединение с сервером вернётся к нему же, получится петля, и через этот прокси перестанет работать всё. Если у вас есть правило «Любое приложение · любой адрес → Через прокси», добавьте клиент в Приложения с маршрутом Напрямую: правило для конкретного приложения важнее правила для любого, см. Правила.

В режимах Спрашивать и Блокировать всё клиенту нужно явно разрешить выход к серверу. Добавьте его в Приложения с маршрутом Напрямую или ответьте Разрешить со сроком Навсегда в окне вопроса. Иначе соединение клиента с сервером будет заблокировано или будет ждать ответа, и все приложения на этом прокси останутся без сети. В режимах Только прокси и Тихий с настройками по умолчанию ничего делать не нужно. Подробнее о режимах — Режимы файрвола.

Если клиент выключен или завис, приложения на этом прокси остаются без сети и напрямую не уходят. Готовая пошаговая настройка — в рецепте Поверх sing-box, Xray или Clash.

Подробнее: localhost, UDP и HTTP-порт клиента
  • Соединения на адрес и порт любого прокси из списка всегда идут напрямую, правила к ним не применяются. Соединения с 127.0.0.1 и ::1 закрывают встроенные правила, см. Список правил.
  • Через SOCKS5 Routekeeper передаёт только TCP, даже если клиент умеет UDP. Поэтому переключатель Блокировать UDP и QUIC нужен и здесь.
  • Если клиент даёт только HTTP-порт, выберите тип HTTP. Порт mixed принимает и SOCKS5, и HTTP.

Рабочий прокси

В офисе прокси обычно выдаёт IT-отдел: адрес, порт (часто 3128 или 8080) и, может быть, логин и пароль.

  1. Добавьте прокси: Название «Офис», Тип HTTP, Сервер и Порт от IT-отдела, Логин и Пароль, если нужны. Тип HTTPS выбирайте, только если IT-отдел сказал, что прокси принимает TLS.
  2. Нажмите Проверить. Если ответ «HTTP-прокси ответил 403 …», прочитайте пункт про порт 80 ниже.
  3. Решите, что пойдёт через рабочий прокси:
    • приложения целиком, например рабочий мессенджер: маршрут «Офис» в разделе Приложения;
    • адреса компании из любых приложений: правило «Любое приложение · *.corp.example → Через прокси «Офис»» в разделе Правила. Для внутренних сетей добавьте правило с подсетью, например 10.0.0.0/8. Такое правило важнее маршрута приложения: браузер ходит через ваш обычный прокси, а сайты компании — через офисный.

Ограничения:

  • Только вход по логину и паролю (Basic). Вход Windows — NTLM, Kerberos, Negotiate — не поддерживается. Такой прокси ответит «HTTP: прокси требует авторизацию (407)».
  • PAC-файлы и автонастройка прокси (WPAD) не поддерживаются. Если компания раздаёт настройки PAC-файлом, откройте его в браузере и найдите строку вида PROXY proxy.corp.example:3128, или спросите адрес у IT-отдела. Адреса, которые PAC-файл отправляет на прокси, перенесите в правила.
  • Только туннели. Routekeeper открывает через HTTP-прокси туннель (CONNECT) для любого соединения, в том числе к порту 80. Многие офисные прокси разрешают туннели только на порт 443. Тогда сайты по HTTPS работают, а сайты по HTTP и кнопка Проверить получают «HTTP-прокси ответил 403 …».
  • По HTTP логин и пароль передаются открытым текстом. Внутри офисной сети это обычно приемлемо. Через интернет используйте HTTPS-прокси.

Готовый сценарий — в рецепте Рабочий прокси для внутренних адресов.
