Проверка и мониторинг: куда ушло каждое соединение

Routekeeper показывает, что идёт через прокси, что напрямую и что прошло мимо. Начните с проверки за минуту, а для полной уверенности сверьтесь со своим сервером.

Проверять можно в пяти местах, от простого к подробному.

Строка меню

Работает ли прокси и какой IP видят сайты.

Обзор

Главное в одной строке и что с этим делать.

Монитор

Каждое соединение: какое приложение, куда и каким маршрутом.

Мимо прокси

Что ушло напрямую у приложений, которые должны идти через прокси.

Ваш сервер

Независимая проверка: приходят ли соединения от вашего Mac.

Проверка за минуту

  1. Нажмите значок Routekeeper в строке меню. Если всё работает, под названием будет зелёная строка состояния, а под ней — строка вида IP 203.0.113.10 · NL. Это внешний IP, который видят сайты, когда трафик идёт через основной прокси (тот, через который идёт больше всего приложений), и код страны. Пока проверка идёт, там написано Проверяем IP….
  2. Сравните этот адрес с вашим обычным: они должны отличаться. Если прокси — ваш сервер, это будет его IP.
  3. Проверьте само приложение. В браузере, который идёт через прокси, откройте любую страницу, показывающую ваш IP. В Терминале, если он идёт через прокси, выполните команду. Адрес должен совпасть с IP в строке меню. 
    curl https://ipinfo.io/ip
  4. Если строки с IP нет, строка состояния будет оранжевой или серой. Откройте Обзор: там написано, что случилось и что делать.

IP в строке меню показывает, что прокси работает. Он не доказывает, что через прокси идёт конкретное приложение. Для этого нужен шаг 3 или монитор.

Каждый прокси можно проверить и отдельно: раздел Прокси, кнопка Проверить. Она покажет «Работает», задержку и внешний IP или текст ошибки. Подробно — на странице «Прокси», в разделе «Проверка».

Подробнее: откуда берутся IP и задержка

Routekeeper сам открывает соединение через прокси с сервисом ipinfo.io на порт 80 и спрашивает внешний адрес и страну. Задержка — время, за которое открывается соединение через прокси. Это несколько обменов с сервером, поэтому для далёкого исправного сервера 500–800 мс — нормально.

Строка меню перепроверяет основной прокси, когда вы её открываете, но не чаще раза в минуту. Пока основной прокси недоступен, он перепроверяется раз в минуту сам. Что ещё Routekeeper отправляет в сеть — на странице «Конфиденциальность».

Обзор

Главный экран окна Routekeeper, ⌘1. Сверху одна строка о самом важном. Ниже — что ждёт вашего ответа, маршруты, счётчики и что идёт через прокси прямо сейчас.

Под заголовком

Здесь появляются строки, когда есть что сделать:

  • Соединения мимо прокси за последний час (или DNS-запросы напрямую за последний час, если были только они) — с приложением, у которого их больше всего. Кнопка Подробнее открывает раздел Мимо прокси.
  • Ждут ответа: N — в режиме Спрашивать программы ждут вашего решения. Кнопка Ответить выводит окно вопроса вперёд. Подробно — режим «Спрашивать».

Маршруты

По строке на каждый прокси, через который идут маршруты. Последняя строка — Напрямую: всё остальное идёт через ваше обычное подключение.

  • Точка: зелёная — прокси отвечает, оранжевая — отвечает медленно, красная — не отвечает, серая — ещё не проверен.
  • Имя, страна и внешний IP по последней проверке.
  • Задержка. От 1500 мс к ней добавляется «медленно». Для далёкого исправного сервера 500–800 мс — нормально.
  • Что идёт по маршруту: значки и имена приложений и сервисов. Нажмите, чтобы раскрыть весь список. Нажатие на пункт открывает его правило в разделе Приложения или Правила.
  • Скорость сейчас, а если прокси несколько — и доля каждого.
  • Меню «…»: Проверить снова, Перевести маршруты на (переводит маршруты только этого прокси), Все прокси….

Если прокси не отвечает, его строка подсвечена, и под ней две кнопки: Перевести на «…» (на другой прокси, по возможности на тот, что ответил на проверку) и Проверить снова. Кнопка Проверить все — на панели инструментов окна, ссылка Все прокси — рядом с заголовком Маршруты. Пока Обзор открыт, Routekeeper перепроверяет прокси из маршрутов, но каждый не чаще раза в минуту.

Перевести все приложения на другой прокси одним движением можно с панели внизу боковой колонки или из меню значка в строке меню (там — если прокси два и больше). Подробно — «Перевод на другой прокси».

Счётчики и «Сейчас через прокси»

  • Карточка Мимо прокси: сколько таких соединений было и с какого времени идёт счёт, какое было последним. Ссылка Подробнее ведёт в раздел.
  • Карточка трафика: скорость через прокси сейчас, сколько передано с начала счёта и график за 3 минуты. Ссылка Монитор.
  • Сейчас через прокси: приложения, которые передавали данные через прокси за последнюю минуту, самые активные сверху. Для каждого — по правилу какого сервиса оно попало на прокси, через какой прокси (если их несколько), сколько соединений и скорость. Здесь видны и приложения, которые идут через прокси только по правилу сервиса. Показаны первые пять, остальные — в мониторе.

Монитор

Список соединений: какое приложение, куда и каким маршрутом. Откройте Монитор в боковой колонке (⌘5) или в меню значка в строке меню.

Счётчики — это фильтры

Сверху пять карточек: Через прокси, Напрямую, Заблокировано, Мимо прокси, Ошибки. На каждой — число и доля от всех соединений. Нажмите карточку, и в списке останутся только эти соединения. Нажмите ещё раз, чтобы снова показать все. Рядом карточка Трафик прокси: скорость сейчас и сколько передано через прокси с начала счёта.

Поле поиска в панели инструментов ищет по домену, IP и имени приложения.

Три вида

Переключатель вверху окна. Фильтр и поиск действуют во всех трёх видах.

  • Соединения — таблица: Приложение, Хост, Маршрут, ↑ / ↓, Время. Столбец Протокол скрыт: чтобы его показать, нажмите правой кнопкой на заголовок таблицы. В столбце Маршрут — имя прокси, Напрямую, Заблокировано, Ошибка, Ждёт ответа или вид соединения мимо прокси. Объём данных считается только для соединений через прокси. Таблица показывает последние 500 найденных соединений. Если их больше, под заголовком окна написано «показаны последние 500».
  • По приложениям — сводка по каждому приложению: сколько соединений, сколько через прокси, напрямую и заблокировано, сколько проблем (мимо прокси и ошибки), трафик и последний адрес. Двойное нажатие или Показать соединения в меню строки открывают соединения этого приложения.
  • Карта — куда в мире уходит трафик. О ней ниже.

Строка соединения

Выберите строку, и под таблицей появится панель с подробностями: IP, номер процесса (PID), Решение (почему соединение пошло так: какое правило, режим, автоматическое разрешение), Длительность. Для соединений через прокси — ещё Задержка прокси и Трафик. Для ошибки написана её причина, для соединения мимо прокси — совет.

Кнопки на панели:

  • Создать правило… — открывает редактор правила, уже заполненный этим приложением и адресом.
  • Через «…» — сразу добавляет правило: это приложение и этот адрес через основной прокси.
  • Блокировать хост — сразу добавляет правило, которое блокирует этот адрес для этого приложения.

Правая кнопка на строке открывает меню: Создать правило…, Блокировать этот хост, Этот хост через «…», Скопировать хост, Скопировать IP. Для нескольких строк — Скопировать хосты или ⌘C.

Пауза, экспорт и очистка

  • Пауза останавливает обновление списка, чтобы его было удобно читать. Счётчики при этом продолжают считать. Кнопка Продолжить возвращает обновление.
  • Экспорт сохраняет в файл CSV все соединения, подходящие под текущий фильтр и поиск, а не только 500 показанных. Столбцы: time, app, process, host, ip, port, protocol, route, bytes_up, bytes_down.
  • Очистить очищает список и сбрасывает все счётчики, включая Мимо прокси и время «с …» в разделе Обзор.

Карта

  • Линии идут от этого Mac к странам, куда уходят соединения. Соединения через прокси нарисованы через страну прокси. Цвета: зелёный — через прокси, синий — напрямую, красный — мимо прокси, оранжевый — ошибки, серый — заблокировано.
  • Положение Mac определяется по часовому поясу.
  • Меню Все приложения оставляет на карте одно приложение. По трафику и По соединениям меняют размер отметок. Объём трафика известен только для соединений через прокси.
  • Масштаб: ⌘+ приблизить, ⌘− отдалить, ⌘0 весь мир.
  • Рядом — список стран. В отдельных строках Глобальные сети и Локальная сеть и прочие. Сети доставки контента отвечают из ближайшей к вам точки, а страна в базе для них — только адрес регистрации, поэтому на карте их нет.
  • База стран встроена в приложение. Адреса для карты никуда не отправляются.
Подробнее: что и сколько хранится
  • Сетевое расширение держит последние 5000 соединений в памяти и на диск их не пишет. После перезапуска расширения или Mac список начинается заново.
  • Счётчики считают с запуска расширения или с последнего Очистить.
  • Пока тумблер Routekeeper включён выключен, соединения не записываются.
  • Счётчик Напрямую включает и соединения мимо прокси: они тоже ушли напрямую. Фильтр Напрямую их не показывает, они в фильтре Мимо прокси.

Мимо прокси

Раздел Мимо прокси (в версии 0.2.1 — Утечки; так же назывались счётчик в мониторе и карточка в разделе Обзор), ⌘6. Здесь соединения приложений, которые должны идти через прокси, но пошли напрямую. Если таких нет, раздел пуст: Соединений мимо прокси не видно.

Строки сгруппированы по процессу и виду, поэтому два помощника одного приложения дают две строки с одним названием. В строке — приложение, вид, сколько раз (× N), до четырёх адресов, совет и кнопка исправления. Сверху самые серьёзные.

Браузеры: DNS через HTTPS вместо блокировки

Если браузеру закрыть порт 53, он перестанет открывать сайты. Поэтому для браузеров кнопки Блокировать DNS нет. Вместо неё включите в самом браузере «DNS через HTTPS» (DoH). Тогда браузер узнаёт адреса сайтов внутри обычного HTTPS-соединения, а оно идёт через прокси вместе с остальным трафиком.

БраузерГде включить
ChromeВставьте в адресную строку chrome://settings/security. Включите «Использовать безопасный DNS-сервер» и выберите поставщика из списка, а не текущего.
Edgeedge://settings/privacy → раздел «Безопасность» → «Использовать безопасный DNS…». Выберите поставщика из списка.
Firefoxabout:preferences#privacy → «DNS через HTTPS» → «Повышенную защиту» или «Максимальную защиту».
Bravebrave://settings/security → «Использовать безопасный DNS-сервер». Выберите поставщика из списка.

Названия зависят от версии браузера. Если не нашли, введите «DNS» в поиске по настройкам. После включения перезапустите браузер, и новые строки DNS мимо прокси для него появляться перестанут. Пошагово — в рецепте «DNS через HTTPS в браузере».

Подробнее: какой вариант DoH надёжнее и какие браузеры распознаются
  • С «текущим поставщиком» в Chrome, Edge и Brave и с «Защитой по умолчанию» или «Повышенной защитой» в Firefox браузер может вернуться к обычному DNS, если безопасный недоступен. «Максимальная защита» в Firefox и выбранный из списка поставщик в Chrome, Edge и Brave так не делают.
  • Браузерами Routekeeper считает: Chrome (все каналы), Chromium, Edge (кроме Canary), Brave, Arc, Vivaldi, Opera, Firefox (вместе с Developer Edition и Nightly), Zen, Waterfox и Яндекс Браузер.
  • Safari узнаёт адреса через системную службу macOS, поэтому его запросы DNS в Мимо прокси не попадают.
  • Служебные запросы ipv4only.arpa и _dns.resolver.arpa одинаковы у всех и ничего о вас не говорят. Routekeeper их не отмечает.

Уведомления

В Настройки → Основные → Уведомления два переключателя, оба включены: Об утечках мимо прокси и О соединениях, которые прокси не смог установить. Чтобы не засыпать вас сообщениями, Routekeeper присылает о каждом виде проблемы у одного приложения не больше одного уведомления за 10 минут.

Уведомления приходят, пока приложение Routekeeper запущено, даже если его окно закрыто. Разрешение на них macOS спрашивает при первом запуске. Если вы отказали, включите их в Системные настройки → Уведомления → Routekeeper.

Что замечается, а что нет

Routekeeper проверяет только приложения, у которых весь трафик идёт через прокси, то есть с маршрутом Через прокси в разделе Приложения. То, что приложение направлено напрямую или идёт через прокси только по отдельным адресам, он считает вашим решением, а не ошибкой.

Подробнее: точные правила проверки
  • Какое приложение считается «через прокси». Routekeeper берёт правило, которое сработало бы для произвольного TCP-соединения этого приложения на неизвестный адрес. Если это правило ведёт через прокси, приложение проверяется. Подходит маршрут приложения, а также общее правило «любое приложение → прокси».
  • DNS — это порты 53 и 853. По UDP такие запросы через прокси не идут: прокси передают только TCP. DNS через HTTPS — это обычное HTTPS-соединение на порт 443, оно идёт через прокси и мимо прокси не считается.
  • Процесс мимо правила проверяется только для TCP и только для правил «всё приложение → прокси». Процесс должен лежать внутри пакета этого приложения. Если правило задано для консольной программы, подходит любая другая консольная программа того же разработчика (Team ID).
  • История. Раздел показывает соединения, которые ещё есть в мониторе. Счётчик в разделе Обзор помнит и более старые, пока вы не нажмёте Очистить или расширение не перезапустится.

Проверка на своём сервере

Самая независимая проверка — посмотреть на сервере, приходят ли соединения от вашего Mac. Команды ниже — для сервера, поставленного по инструкции «Свой прокси-сервер»: там прокси — Caddy на порту 443.

  1. Узнайте свой обычный адрес. Откройте в браузере, который идёт напрямую (например, в Safari, если вы не направляли его через прокси), любую страницу, показывающую ваш IP. Запишите его.
  2. Подключитесь к серверу по SSH, как при установке.
  3. Посмотрите открытые соединения с Caddy на порту 443: 
    ss -tnp state established '( sport = :443 )'
    В столбце Peer Address:Port — адреса, откуда пришли соединения. Среди них должен быть ваш адрес из шага 1, а в последнем столбце упомянут caddy. Адрес может быть записан как [::ffff:198.51.100.7]:51234, это тот же IPv4-адрес.
  4. Посчитайте соединения только с вашего адреса и посмотрите, как число меняется. Подставьте адрес из шага 1: 
    watch -n 2 "ss -tn state established '( sport = :443 )' | grep -c ВАШ_IP"
    Откройте на Mac приложение, которое идёт через прокси, и начните им пользоваться: число вырастет. Закройте его — число уменьшится, когда соединения закроются. Выход из watch — Ctrl+C.

Учтите: Routekeeper сам проверяет прокси через этот же сервер, поэтому одно-два соединения могут появляться, даже когда приложения закрыты.

На Mac

Откройте Терминал и посмотрите открытые соединения с сервером. Подставьте IP сервера:

netstat -an -p tcp | grep ESTABLISHED | grep 'IP_СЕРВЕРА.443'

Каждая строка — одно соединение с прокси. В macOS порт пишется через точку: 203.0.113.10.443. Если в Routekeeper сервер указан доменом, узнайте его IP:

dig +short ДОМЕН
Подробнее: какой процесс держит эти соединения

Соединения с прокси открывает сетевое расширение Routekeeper от имени приложений, поэтому имён самих приложений здесь нет: какое приложение куда пошло, смотрите в мониторе. Чтобы увидеть процесс, нужен пароль администратора:

sudo lsof -nP +c 0 -iTCP@IP_СЕРВЕРА:443 -sTCP:ESTABLISHED

В столбце COMMAND будет процесс, имя которого начинается с Routekeeper. Если там другая программа, значит, к серверу подключается ещё кто-то, например клиент прокси.
