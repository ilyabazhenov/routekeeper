Firewall modes: what happens to the rest

The mode decides what to do with a connection that has neither a route nor a rule. Start with Proxy Only, and turn on the stricter modes when you need them.

Routekeeper decides what happens to each new connection in a fixed order. First it looks at the app’s route and the rules. The mode comes into play only if no rule matched.

So the mode doesn’t change what you’ve already set up: an app with the Through Proxy route goes through the proxy in any mode. How Routekeeper picks a rule when several match is explained in Which rule wins.

Four modes

ModeConnection without a ruleWho it’s for
Proxy OnlyGoes direct, with no questions. The firewall is off.Everyone at the start. Anyone who only needs a route through the proxy for some apps.
SilentSilently allowed (the default) or silently blocked. No prompts.Anyone who wants to quietly collect a list of programs that go online, or to silently deny everything new.
AskWaits for your answer in a prompt. With no answer, it’s allowed after 60 seconds.Anyone who wants to know about every new program on the network and decide for themselves.
Block AllBlocked.Strict isolation: only what you’ve explicitly allowed can go online.

Start with Proxy Only. This mode is on after installation. First set up routes through the proxy and make sure in Overview that everything works. You can turn on the firewall later, and your rules won’t be lost.

Where to switch the mode

  • In the Routekeeper window: the panel at the bottom of the sidebar, the Mode row.
  • In the menu bar: click the Routekeeper icon. The modes are listed in the Mode group.
  • In settings: Settings… → Firewall (⌘,). The settings for the Silent and Ask modes and the Always Ask list are there too.

The mode switches right away, without confirmation. It applies to new connections and doesn’t touch the ones already open. Hover over a mode to see a tooltip about what it does.

Details: the order in which Routekeeper decides
  1. If Routekeeper is turned off with the Routekeeper On switch, the connection goes direct, and nothing else is checked.
  2. A connection to one of your proxy servers (the same address and port as in the Proxy section) goes direct.
  3. The most specific matching rule, including app routes and services. The order of rows in the list doesn’t matter.
  4. A connection to this same Mac (loopback), if Settings → Network → Leave localhost alone is on (it’s on by default).
  5. The mode.

Routekeeper has built-in rules with the source Default: the addresses 127.0.0.0/8 and ::1 go direct, and so does Routekeeper itself. That’s why the window and the menu bar icon work in any mode.

An app with the Ask route, or a rule with the Ask action, shows a prompt in any mode, even in Proxy Only. Automatic permissions (Apple software, apps installed earlier) work only in Ask mode.

Proxy Only

The firewall is off. Only your routes and rules work: some traffic goes through the proxy, some is blocked, and everything else goes direct, as if Routekeeper weren’t there. There are no prompts.

This mode is on after installation, and for most people it’s enough. The monitor and the Leaks section work in it too.

Silent

Connections without a rule are handled silently, according to a setting you choose in advance. There are no prompts. When this mode is selected, two switches appear in Settings → Firewall:

SwitchDefaultWhat it does
Allow connections without a ruleOnOn: connections without a rule go direct. Off: they are silently blocked.
Create rules “for review”OffFor each new program without a rule, Routekeeper records a rule for the whole app: allow or block, depending on the first switch. These rules have the source For Review.

An example: turn on both switches and work as usual for a few days. A list of everything that went online will build up in Rules → Source → For Review. Look through it and block what you don’t need. Then you can move to Ask or Block All. For more about rule sources, see The list of rules.

Details: a “for review” rule applies before the mode

The rule is created at the program’s first connection and then works like any other rule: for any address, including child processes. If you later change Allow connections without a rule, the rules already recorded stay as they were. Change them in the Rules section, or delete them so that the program falls under the mode again.

Ask

When a program without a rule tries to go online, Routekeeper holds the connection and shows a prompt. The program waits until you answer. Your answer is usually saved as a rule, and next time Routekeeper doesn’t ask.

The prompt

The prompt appears on top of all windows and on all desktops, but it doesn’t bring the main Routekeeper window forward. It shows:

  • Title: the program’s name and “wants to connect”. Below it are the address, port and protocol (TCP or UDP).
  • Timer on the right: how many seconds are left before the default answer. It turns orange 10 seconds before the end. If more connections from this program are waiting, you’ll see “+N waiting” next to it.
  • Program details: Path to the file; Signature (Apple, App Store, the developer with their Team ID, Ad-hoc signature or Unsigned); Launched by, the chain of programs that started it, for example Terminal › zsh › curl. For more about signatures, see code signature in the glossary.

Below that, you choose what to save and where it applies:

SettingOptions
DurationOnce: a decision for this connection only. No rule is saved.
While … is running (with the program’s name): the rule works until the program quits, and then it’s deleted.
Forever: a permanent rule. Selected by default.
WhereThe exact address, for example api.example.com.
The whole domain, for example *.example.com: the domain itself and all its subdomains. Selected by default when it’s offered. What the asterisk means is explained in the glossary: wildcard.
Any host :443: any address, but only this port.
Anywhere: any address and any port.
Child processesThe Including child processes of … switch (on): the rule also covers the programs that this program starts.

Below the settings, one line says what rule you’ll get, for example “Rule: curl and its child processes to *.example.com, forever”. With the Once duration, it says that no rule will be saved, and Where and child processes aren’t available.

The answer buttons:

ButtonKeysWhat it does
Block⌘BDenies the connection.
Through Proxy⌘PSends it through a proxy. The proxy that most apps go through is already selected. If you have several proxies, the arrow on the button opens a list. The button isn’t shown until you’ve added at least one proxy.
Allow↩Lets it go direct. In the Rules section, such a rule has the Direct action.

To make a program go through the proxy, choose the While … is running or Forever duration. Routekeeper sends connections through a proxy according to a saved rule.

Gave the wrong answer? Open Rules and choose From Prompt in the Source filter. All the rules made from prompts are there: you can change, turn off or delete them. To undo the last change, press ⌘Z.

If there are many connections

  • There is one prompt per program. While it’s open, new connections from this program wait along with the first one, and the “+N waiting” counter goes up.
  • After you answer, Routekeeper checks the waiting connections against the new rule. If the rule doesn’t cover them (for example, you allowed one address, and they go to another), a new prompt appears.
  • Prompts for different programs are shown one at a time.
  • If a program quits while it’s waiting, its connections are canceled.

Who Routekeeper doesn’t ask

Otherwise, there would be far too many prompts in the very first hour. In Settings → Firewall, in the Ask Mode section, there are two switches, and both are on:

  • Allow software signed by Apple: Apple’s system services and programs go online without a prompt. The exception is the Always Ask list. For each such program, a rule with the source Apple appears.
  • Allow apps installed before Routekeeper: programs that were on the Mac before Routekeeper was installed and are signed by their developer also pass without a prompt. Their rules have the source Installed Before. Routekeeper always asks about unsigned programs.

You can see these programs in the Apps section, in the collapsed Allowed Automatically group.

The Always Ask list holds Apple utilities that scripts and installers often use to go online. Routekeeper asks about them even though they’re signed by Apple. The default list: curl, python3, python, osascript, nc, ssh, ruby, perl, openssl, telnet, ftp, rsync, scp. To add a utility, type its name or signing ID in the field below the list and click Add. To remove one, select its row and click “−”.

Details: the exact conditions for automatic permissions
  • Apple. Applies only if the program has no rules of its own yet. For example, if Safari has a rule for one domain, Routekeeper will ask about the other addresses. The rule is created without child processes: whatever Terminal starts is checked separately.
  • Installed Before. Routekeeper compares the date the app appeared in its folder (or the file’s creation date) with the date Routekeeper was first installed. This covers programs signed by a developer or the App Store, and programs with Ad-hoc signature. Apple programs aren’t included. The rule is created together with child processes.
  • If you turn off Allow software signed by Apple, system services will start asking too. Among them is mDNSResponder, which macOS uses to look up site addresses. Until you answer it or the time runs out, sites won’t open by name. Allow it Forever.

If you don’t answer

  • Wait for an answer: how long the prompt waits. 15 seconds, 30 seconds, or 1, 2, 5 or 10 minutes. The default is 1 minute.
  • If there’s no answer: what to do when the time is up. Allow (the default) or Block. This decision applies only to the connections that were waiting, and no rule is saved. The next time the program tries to connect, the prompt appears again.

To see what will happen if you don’t answer, hover over the timer.

If the Routekeeper app isn’t running

Decisions are made by the network extension, but the prompt is shown by the Routekeeper app. If the app isn’t running, there’s no one to ask. This happens if you clicked Quit Routekeeper, after a restart before you log in, or while the app hasn’t been opened yet.

In that case, the connection of a program without a rule is allowed, and a For Review rule is recorded for it: allow the whole app. From then on, this program goes online without prompts until you change the rule. If you quit Routekeeper while prompts are open, the waiting connections are allowed too.

  • Turn on Settings → General → Open at login. It’s off by default, and after a restart there will be no prompts until you open Routekeeper.
  • From time to time, look through Rules → Source → For Review.

Where you can see what’s waiting for an answer

  • In the Overview section: the Waiting for answer: N line. The Answer button brings the prompt forward.
  • In the menu of the menu bar icon: the Waiting for answer: N item. A mark also appears on the icon itself.
  • Next to Overview in the sidebar: the number of problems. A waiting prompt counts as one.

DNS queries

The Allow DNS queries (UDP 53) switch is off by default, and you usually don’t need it. Most programs look up site addresses through a macOS system service, and that service is signed by Apple and allowed automatically. Turn the switch on if prompts appear because of programs that send DNS queries to port 53 themselves. Then such queries without a rule pass without a prompt. It works only in Ask mode.

If you use a local proxy client

A client such as sing-box, Xray or Clash connects to its server by itself. In Ask mode, Routekeeper will ask about it too, unless it was installed before Routekeeper. Allow it Forever with Anywhere, or give it the Direct route in the Apps section. Otherwise, all the apps that go through it will stop working too. For details, see the recipe On top of sing-box, Xray or Clash.

Block All

Every connection without a rule is blocked. Only connections inside the Mac (loopback) and Routekeeper itself are allowed on their own. Your routes and rules keep working: apps with the Through Proxy or Direct route go online as before.

Everything else will stop working. Browsers and messengers without a route, mail, iCloud sync, updates for macOS and other programs, your proxy client (sing-box, Xray, Clash), and with it all the apps that go through its local port. Routekeeper doesn’t ask for confirmation when you switch modes, so prepare your rules first.

How to prepare

  1. Give a route to every app that needs the network: in the Apps section, choose Through Proxy or Direct. How to add an app is explained in How to add an app.
  2. If you use a local proxy client, give it the Direct route.
  3. Switch the mode to Block All.
  4. Open Monitor and click the Blocked counter. Right-click the row you need and choose Create Rule….
Details: what else isn’t blocked, and what to check
  • Connections to your proxy servers from the Proxy section (the same address and port) aren’t blocked either, whichever program they come from.
  • There is no built-in rule for mDNSResponder, the system name service. If the apps you allowed can’t open sites by name, find blocked mDNSResponder connections to port 53 in the monitor and allow them. Or add /usr/sbin/mDNSResponder in the Apps section with Add → Enter Path… and give it the Direct route.
  • An app’s Ask route works in this mode too: instead of being blocked, the connection shows a prompt.

How to get back

Routekeeper itself isn’t blocked, so its window and menu work. Choose Proxy Only in the Mode row on the sidebar panel, or in the menu of the menu bar icon. You can also use Settings → Firewall.

If you urgently need to give the network back to all programs, turn off the Routekeeper On switch in the icon’s menu or on the sidebar panel. Then all connections go direct, with no rules and no mode. How this differs from other ways to turn Routekeeper off is explained in How to turn it off quickly.
