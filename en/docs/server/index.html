Your own proxy server in 15 minutes

One command turns a rented VPS into an HTTPS proxy for Routekeeper. From the outside the server looks like an ordinary website, and only you hold the key to the proxy.

What you get

App → Routekeeper → TLS → your server :443 → internet
  • An HTTPS proxy: HTTP CONNECT inside TLS, served by Caddy with forwardproxy@naive. Nothing but Routekeeper is needed on the Mac.
  • A Let's Encrypt certificate. Without the password the server answers like a plain placeholder website and doesn't reveal that it's a proxy.
  • The server is yours. The script sends nothing anywhere: neither traffic nor the password passes through Routekeeper or its author.
  • TCP only. Calls and voice won't go through such a proxy; see the limitations.

What you need

  • A VPS with Debian 12 or 13 or Ubuntu 24.04, an x86_64 (amd64) CPU, 1 GB of memory or more, a public IPv4 address and root SSH access. The cheapest plan will do.
  • Closer is faster. Every new connection takes about three round trips to the server, so pick the nearest country where the services you need work.
  • Free ports 80 and 443. If the server already runs a website or a VPN panel (nginx, Xray, 3x-ui, Marzban), the script won't touch it — use a separate server.
  • A domain. Your own or a free one from DuckDNS: Let's Encrypt issues the certificate for it.

1Domain

For a free DuckDNS domain:

  1. Sign in at duckdns.org with GitHub or Google.
  2. Create a subdomain. A neutral name is better, without “proxy” or “vpn”.
  3. Put the server's IP into current ip and press update ip.

You won't need the DuckDNS token: the server's IP doesn't change. For your own domain, create an A record with the server's IP at your registrar. The record starts working within a couple of minutes.

2Log in to the server

Open Terminal (Applications → Utilities) and connect using the IP from your hosting provider's email:

ssh root@IP

Answer yes to the “fingerprint” question, then enter the root password. The password isn't shown as you type — that's expected.

3Install

On the server, run one command with your domain:

curl -fsSL https://getroutekeeper.app/server.sh | bash -s -- --domain name.duckdns.org

If your provider gave you a sudo user instead of root, use | sudo bash -s --. It takes a minute or two. The script:

  1. checks that the domain points at this server and that ports 80 and 443 are free;
  2. installs Caddy with forwardproxy@naive and verifies the build's checksum;
  3. creates a login and a long random password;
  4. gets a Let's Encrypt certificate and sets up a placeholder site for anyone who comes without the password;
  5. turns on BBR, which noticeably speeds up connections over long routes;
  6. installs fail2ban, which blocks SSH password guessing;
  7. turns on automatic security updates (the server never reboots by itself);
  8. checks that the proxy works and prints a line for Routekeeper.

It's wise to read a script from the internet before running it. Then do this instead:

curl -fsSLO https://getroutekeeper.app/server.sh
less server.sh
bash server.sh --domain name.duckdns.org
FlagWhat it does
--new-passwordCreates a new login and password.
--no-bbrLeaves TCP settings as they are.
--no-fail2banDoesn't install fail2ban.
--no-auto-updatesDoesn't turn on automatic updates.
--uninstallRemoves the proxy. BBR, fail2ban and updates stay.
--lang enEnglish messages, if the script speaks another language.

4Routekeeper

At the end the script prints a line like https://u1a2b3c…:…@name.duckdns.org:443.

  1. Select the line in Terminal and copy it (⌘C).
  2. In Routekeeper, open Proxy and press ⌘V or the Paste button under the list. A new proxy opens with the fields filled in.
  3. DNS through proxy and Block UDP and QUIC are already on — leave them and press Add.
  4. Check should show your server's IP.
  5. In Rules, send the apps you want through this proxy.
The line is the key to your proxy: don't publish it or paste it into chats. Run the install command again to see it, or find the login and password on the server in /etc/caddy/proxy-credentials.

Securing the server

Bots guess root passwords around the clock: our test server saw about 11,000 attempts a day. fail2ban blocks each such address after five failures, but it's safer to turn password login off entirely and use a key. On the Mac:

ssh-keygen -t ed25519 -f ~/.ssh/my_server
ssh-copy-id -i ~/.ssh/my_server.pub root@IP
ssh -i ~/.ssh/my_server root@IP

If the last command let you in without the root password, turn passwords off in that same session:

printf 'PasswordAuthentication no\nPermitRootLogin prohibit-password\n' > /etc/ssh/sshd_config.d/10-keys-only.conf
systemctl reload ssh
Keep this session open until you've checked key login in a new Terminal window. If other apps manage the server with the root password (the Amnezia client, for example), they'll need a key afterwards too.

If it didn't work

  • “The A record … must point at …” — the domain hasn't updated yet or points elsewhere. Check the IP in DuckDNS, wait a couple of minutes and run the command again.
  • “Ports 80 and 443 are taken” — the server already runs a website or a VPN panel. Use a separate server.
  • “Caddy couldn't get a Let's Encrypt certificate” — usually ports 80 and 443 are closed in the hosting panel (firewall, security group). Open them and run the command again. If you reinstalled many times in a week, Let's Encrypt may temporarily refuse the domain: pick another DuckDNS name.
  • “An x86_64 server is required” — ARM servers aren't supported yet.
  • Routekeeper can't check the proxy — the Server field must hold the domain, not the IP, and the whole line must be pasted.
  • It's slow — pick a closer server. On a route with a ~200 ms ping a single connection gets about 3–4 MB/s.
  • The proxy worked and then stopped — some networks recognise TLS proxies by their traffic pattern. The fallback is sing-box or Xray on the same server with their local SOCKS5 on the Mac, see Your proxy. Your Routekeeper rules stay as they are.

If you're stuck, open an issue on GitHub with the script's output. Remove the proxy line and the password from it first.
