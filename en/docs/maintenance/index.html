Updates and removal

Requirements, updating the app and the extension, moving to the new version, ways to turn it off and complete removal. Also where Routekeeper keeps its data and where it connects to on its own.

Routekeeper has two parts: the app with the menu bar icon, and the network extension, which runs in the system and applies the rules. They are updated and removed a little differently, so each part is described separately below.

Requirements

  • macOS 14 Sonoma or later.
  • A Mac with Apple silicon or Intel. The same build works on both.
  • An administrator account. Without it, macOS won’t allow the network extension.
  • The Applications folder. macOS installs system extensions only for apps in /Applications. If you run Routekeeper from the disk image or from Downloads, the welcome screen offers Move to Applications and Relaunch. The old copy in Applications then goes to the Trash.
  • Language. The interface is in English or Russian, depending on the system language. In the English interface, a few new labels may still be in Russian for now.
  • Other VPNs and network filters can get in Routekeeper’s way: see Other VPNs and network extensions.

Routekeeper comes as the disk image Routekeeper.dmg on the website and on GitHub Releases. The build is signed with a developer certificate and checked by Apple (notarized). The first time you open it, macOS still asks whether to open a program from the internet. Click “Open”. Installation is described step by step in the Quick start.

Updates

The app

  • Routekeeper checks for updates by itself once a day if Check for updates automatically is on (Settings → General, the Updates section). It’s on by default.
  • To check yourself: Settings → General → Check for Updates…. Or, while the Routekeeper window is open, the Routekeeper menu at the top of the screen → Check for Updates….
  • When a new version comes out, Routekeeper shows a window that offers to update. The new version is installed only after you confirm, and then Routekeeper restarts.
  • Rules, proxies and settings are kept when you update. What changed in each version is on the What’s new page.

The network extension

The extension is updated separately, when you say so. Until you update it, the previous one keeps working, and the rules apply as before.

  1. After the app updates, the banner “A network extension update is available (current: …).” appears at the top of the window. The menu of the menu bar icon has the Extension Update Available item.
  2. Quit the apps that must not go online around the proxy.
  3. Click Update… on the banner, then Update Now. Later puts the update off.
  4. After a few seconds, the extension restarts in the new version. Usually you don’t need to restart the Mac.

While the extension restarts, connections through the proxy break, and for a couple of seconds new connections may go direct, around the proxy. That’s why the extension doesn’t update by itself. For details, see Limitations.

You can also update the extension in Settings → Extension: the Update Extension (current: …) button in the Status section. It updates right away, without asking again.

If the “The network extension isn’t responding” banner appears after the update, click Reinstall Extension. If that doesn’t help, restart your Mac. For details, see Reinstalling and stopping the extension.

From version 0.2.x to the next one, a normal update won’t work: the old version only tells you about the new one and gives a link to the website. How to move to it is described in the next section.

Moving from 0.2.x to the next version

This section is about the version that comes out after 0.2.1. Until it’s on GitHub Releases, you don’t need to do anything.

In the next version, Routekeeper’s system app identifier (bundle ID) changes from dev.ilyabazenov.appproxy to app.getroutekeeper.mac. For macOS, this is a different app. Permissions, opening at login, notifications and window settings are tied to the identifier, and only the old app can remove the old extension. That’s why version 0.2.x won’t install the new version over itself: it only tells you about it and gives a link to the website.

Steps

  1. If you like, save your rules to a file: Rules → Import and Export → Export…. Usually you don’t need this, since the rules move over by themselves, but this way you’ll have a copy. Proxy passwords aren’t saved to the file.
  2. In the old Routekeeper, open Settings → Extension and click Delete… → Delete. The old extension and its filter and proxy are removed from the system, and the rules stay on disk.
  3. Click the menu bar icon → Quit Routekeeper. Move the old Routekeeper from Applications to the Trash.
  4. Download the new version from the website, drag Routekeeper to Applications and open it from there.
  5. Go through the welcome screen: allow the network extension, network content filtering and the proxy configuration again (how to do it). Allow notifications when macOS asks.
  6. If Routekeeper used to open at login, turn this on again: Settings → General → Open at login.

On first launch, the new extension moves your rules, proxies with passwords and mode settings by itself. If you had apps or services going through a proxy, then after the three permissions the window opens straight to your sections, without the proxy and app steps.

If the old extension is still there

If you skip step 2, the old extension keeps running and handling traffic next to the new one. The rules of the two versions will get in each other’s way. The new version notices this and shows the banner “An extension from an old version of Routekeeper is running”.

  • macOS 15 and later. Click Open System Settings on the banner, or open System Settings → General → Login Items & Extensions → Network Extensions. Turn off “Routekeeper Network Extension”: this is the old extension. “Routekeeper Extension” is the new one. Leave it alone.
  • macOS 14. macOS 14 has no “Login Items & Extensions” section, so there’s nowhere to turn off the old extension. That’s why on macOS 14 you must do step 2 before you install the new version. If the new version is already installed and the banner has appeared, report a problem and attach diagnostics.

You can check whether the old extension is on with a command in Terminal. The line with dev.ilyabazenov.appproxy.extension must not have the [activated enabled] mark.

systemextensionsctl list

What moves over and what doesn’t

Moves over by itselfNeeds to be set up again
Rules, proxies with logins and passwords, the mode, the firewall and network settings, downloaded service listsThe three macOS permissions, opening at login, permission for notifications, window settings: notification switches, automatic update checks, the selected settings tab

The new version deletes the old version’s caches in ~/Library on first launch: traffic map data (about 55 MB) and downloaded service lists. The old version’s window settings file stays, and you can delete it: see What stays on disk.

Details: how the settings move

Versions 0.2.x keep settings in /Library/Application Support/AppProxy, the new version in /Library/Application Support/Routekeeper. On first launch, the new extension moves the files from the old folder to the new one, if the new folder doesn’t have its own settings yet, and deletes the emptied old folder. Rules for Routekeeper itself are switched to the new identifier.

It’s better not to go back to 0.2.x after the move: the old version looks for its settings in the old folder, which no longer exists, and starts with clean settings. If you must go back, export your rules first.

The extension’s identifier changed too: dev.ilyabazenov.appproxy.extension → app.getroutekeeper.mac.extension. The subsystem of the internal log is now app.getroutekeeper.mac.

How to turn it off

There are four ways to “turn off” Routekeeper, and they do different things.

WayWhereWhat happensHow to undo it
The Routekeeper On switchThe menu of the menu bar icon; the panel at the bottom of the window’s sidebarRules don’t apply, and all connections go direct. The filter and proxy stay in the system. The monitor doesn’t record.Turn the switch on.
Quit RoutekeeperThe icon’s menuOnly the window and the icon close. The extension keeps applying the rules. There are no notifications. In Ask mode, no prompts are shown: connections are allowed, and Routekeeper records “For Review” rules.Open Routekeeper from Applications.
Stop…Settings → ExtensionThe filter and proxy are turned off in the system: everything goes direct, and firewall rules don’t apply. The extension and the rules stay.Settings → Extension → Reinstall: the filter and proxy turn on by themselves. The switch won’t bring them back.
Delete…Settings → ExtensionThe network extension and both of its configurations are removed from the system. The rules stay on disk.Go through the welcome screen again: three permissions. The rules come back by themselves.

For an everyday “turn it off for a minute”, use the switch. For more about stopping and reinstalling, see Troubleshooting.

Remove Routekeeper

  1. If opening at login is on, turn it off: Settings → General → Open at login.
  2. Open Settings → Extension, and in the Danger Zone section click Delete…, then Delete. Routekeeper’s network extension, filter and proxy are removed from the system. macOS may ask for the administrator password.
  3. Click the menu bar icon → Quit Routekeeper.
  4. Move Routekeeper from the Applications folder to the Trash.

Rules and proxies stay on disk and come back if you install Routekeeper again. To delete them too, see the next section.

If you move the app straight to the Trash without step 2, macOS usually removes the extension by itself, sometimes after a restart. Check with the command from the next section, and check in System Settings → Network that no Routekeeper configurations are left there.

You can delete all of this with commands in Terminal. Run them after you’ve removed Routekeeper with the steps above. Copy and run each command separately.

The first command deletes your rules and proxy passwords for good. If you might need them, export your rules first and save the passwords somewhere else.

Rules, proxies and passwords (macOS asks for the administrator password):

sudo rm -rf "/Library/Application Support/Routekeeper"

Service lists, caches and the app’s internal files:

rm -rf ~/Library/Application\ Support/app.getroutekeeper.mac ~/Library/Caches/app.getroutekeeper.mac ~/Library/HTTPStorages/app.getroutekeeper.mac

Window settings:

defaults delete app.getroutekeeper.mac
Details: leftovers from versions 0.2.x

Versions up to and including 0.2.1 used the old identifier. If you installed them, delete these files too:

sudo rm -rf "/Library/Application Support/AppProxy"
rm -rf ~/Library/Application\ Support/dev.ilyabazenov.appproxy ~/Library/Caches/dev.ilyabazenov.appproxy ~/Library/HTTPStorages/dev.ilyabazenov.appproxy
defaults delete dev.ilyabazenov.appproxy

If a folder doesn’t exist, the command simply does nothing. In that case, defaults delete says that the domain doesn’t exist. This isn’t an error.

Check that the extension is removed

systemextensionsctl list

The output must not have a line with app.getroutekeeper.mac.extension (or with dev.ilyabazenov.appproxy.extension from versions 0.2.x). If there is such a line, marked to be removed after a restart (waiting to uninstall on reboot), restart your Mac.

Data and network

Where the settings are kept

  • Rules, proxies with passwords and settings are in the extension’s file /Library/Application Support/Routekeeper/config.json. Only an administrator can read it. The Routekeeper window gets the settings without passwords, and the extension itself runs the proxy checks.
  • The connection log for the monitor is kept only in the extension’s memory: the last few thousand entries. It isn’t written to disk and is lost when the extension restarts.
  • The internal log goes to the macOS system log and is kept as long as macOS keeps it, usually a few days.
  • Service lists, map data and window settings are in ~/Library: see What stays on disk.

Opening at login

Open at login (Settings → General) is off by default. When it’s on, Routekeeper is listed in System Settings → General → Login Items (Login Items & Extensions on macOS 15 and later).

Even without it, after a restart the extension, filter and proxy start by themselves, and the rules work. Until you open Routekeeper, there’s no menu bar icon, no notifications and no prompts in Ask mode, and Routekeeper doesn’t check for updates or new service lists.

Where Routekeeper connects on its own

  • To your proxies: to pass on the traffic of the apps you sent there.
  • To ipinfo.io through your proxy: to find out the external IP, the country and the response time. This happens when you click Check, save a proxy or open the list of proxies. The main proxy is also checked when you open the menu or the window (no more than once a minute), a few seconds after the network changes, and once a minute while the check keeps failing. ipinfo.io sees the proxy’s address, not yours.
  • To getroutekeeper.app for updates: once a day and when you click Check for Updates…. If you agree to update, the build itself is downloaded from GitHub Releases.
  • To getroutekeeper.app for service lists: every 12 hours and when you click Check Lists (Settings → General → Service Addresses).

Nowhere else: no analytics, no telemetry, no crash reports. Routekeeper finds the country and network for the traffic map in a built-in database, without going online. For details, see the privacy policy.

Details: addresses and signatures
  • The list of versions: getroutekeeper.app/appcast.xml over HTTPS.
  • The builds themselves: GitHub Releases. Each build is signed with the update key, and Routekeeper won’t install a file whose signature doesn’t match.
  • Service lists: the file domainsets/v1.json from getroutekeeper.app over HTTPS. The file is signed too, and both the app and the extension check its signature.
  • External IP: a GET /json request to ipinfo.io on port 80, through the proxy being checked.

Routekeeper’s own connections aren’t covered by your rules: the app itself has a built-in “direct” rule, and the extension runs the proxy check through the proxy itself.
