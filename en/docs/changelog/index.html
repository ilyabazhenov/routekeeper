Routekeeper offers to update by itself when a new version comes out: see Updates. All builds are on GitHub Releases.

0.3.0 — October 5, 2026

Build 11.

You move to it from 0.2.x by hand, once: see Moving from 0.2.x to 0.3.0.

  • License. Routekeeper routes traffic only with a valid license. It’s tied to one Mac and usually lasts a year. Everything else works without it, so you can set up proxies, apps and rules in advance. The Mac code and the license field are in Settings → License. Two weeks before the license ends, Routekeeper reminds you to renew it. See License.
  • Your own proxy server from the app. The Your Own Server… button in the Proxy section and on the welcome screen opens a wizard: enter the IP and password of a rented server and a domain, and Routekeeper sets up an HTTPS proxy on the server and adds it by itself. No Terminal needed. The server password isn’t saved: Routekeeper logs in with its own key from the keychain. The card of such a proxy gets a Server block to check and update the server, change the proxy password, turn off password logins to the server and remove the proxy from it. See Setting it up from Routekeeper.
  • A new app identifier. The system identifier changes from dev.ilyabazenov.appproxy to app.getroutekeeper.mac. For macOS, this is a new app, so versions 0.2.x only tell you about it and give a link to the website. Remove the old version with its own Delete… button, then install the new one and give the three permissions again. Rules, proxies with passwords and settings move over by themselves. If the old extension is still on, the new version shows a banner and explains how to turn it off. In System Settings, the extension is now called “Routekeeper Extension”.
  • Severity levels in Leaks. Each kind of entry now has its own severity: Process outside the rule is the most serious (red), UDP around the proxy is orange, and DNS around the proxy is the least serious (yellow). If only DNS queries go direct, Overview doesn’t raise the alarm and simply says “DNS queries go direct”. The tip for such an entry explains what the DNS provider sees in this case.
  • A lock when the settings can’t be read. Sometimes the extension can’t read the settings file: the file is damaged, or an older version was installed over newer settings. Routekeeper no longer starts with clean settings and sends all apps direct. Instead, it blocks all connections except connections within the Mac, Routekeeper itself and the system DNS service. The banner offers Check for Updates or Reset Settings…, and a reset keeps the old file. For details, see All connections are blocked.
  • Settings from older versions can always be read. If the file lacks a setting that was added later, that setting gets its default value.
  • New services: TikTok, Reddit, Twitch, Slack, Zoom, GitHub and Figma. There are now 32 services in all.
  • A service adds its app. Along with a service, Routekeeper also adds its Mac app with the same route: for example, Slack, Zoom, Telegram, ChatGPT, Claude, Cursor, JetBrains IDEs. For Claude, the claude command-line program is added too. An app installed later is added by itself. Apps you’ve already given a route don’t change.
  • New services without a new version. The whole service catalog now comes from the website: the services themselves, their addresses, the apps added along with a service, and the browsers for which the Monitor suggests DNS over HTTPS. Before, only the addresses were updated from the website. The catalog is checked every 6 hours instead of 12. The section in Settings is called Service Catalog and shows when the last check was.
  • A faster traffic map. The map is built in the background and doesn’t slow down the window, and the connection dots move smoothly.

0.2.1 — October 3, 2026

Build 10.

  • Through Proxies Now on the Overview screen. Which apps are sending traffic through a proxy right now, how fast, and through which proxy. An app stays in the list for a while after its traffic goes quiet.
  • Fewer false “DNS around the proxy” entries. The service queries ipv4only.arpa and _dns.resolver.arpa are the same for everyone and say nothing about what you do. They’re no longer flagged.
  • Browsers and DNS. If a browser sends its own DNS queries around the proxy, Routekeeper suggests turning on DNS over HTTPS in it. For browsers, it doesn’t show the Block DNS button: without DoH, a browser with port 53 closed would stop opening sites. Recipe: DNS over HTTPS in the browser.
  • The speed graph no longer goes past its edges and shows only its own time window.

0.2.0 — October 3, 2026

Build 9.

  • The Overview screen is the new main screen. At the top, it shows whether everything works, and if not, the most serious problem and a button that fixes it. Below are all routes with the status and speed of their proxies, direct traffic, and connections around the proxy.
  • Moving routes to another proxy from the window and from the menu bar: all apps at once, or one proxy’s routes. Before moving, Routekeeper shows exactly what will move and from where. Afterwards, it lets you undo for a few seconds. For details, see the recipe The proxy stopped answering.
  • Services. A rule for a whole service, for example “YouTube through a proxy”, applies in all apps at once. In rules, a service is written as @youtube. An address you enter yourself wins over a service. The service card shows what the rule matched and checks whether an address is on the list.
  • New services: LinkedIn, Signal, Viber, Proton Mail, Spotify, Notion, JetBrains, and Russian ones: government sites, banks, popular sites. The Russian services are added with the Direct route. There are 25 services in all.
  • Service address lists are updated from the website every 12 hours, without a new app version. The date of the lists and a button to check by hand are in Settings → General → Service Addresses.
  • You can choose services on the Apps screen and on the welcome screen.
  • The prompt in Ask mode suggests the proxy that most apps already go through, and shows how many connections are waiting for an answer. Clicking the prompt no longer brings the main window forward.
  • A proxy’s dot turns orange only when the delay is noticeable: from 1500 ms, with the label “slow”.
  • If the main proxy fails its check, Routekeeper repeats the check once a minute. Before, after a short failure, the menu bar could show for hours that the proxy was unreachable.
  • When two proxies have the same name, the route menu tells them apart by type and port.
  • Diagnostics get a fresh list of connections from the extension, even if the monitor is closed.

0.1.0 — October 3, 2026

Build 8. The first public version.

  • A route for each app: Through Proxy, Direct, Block or Ask. Apps are recognized by the developer’s signature, together with their child processes.
  • Rules by address: site name, wildcard *., IP, subnet, port and protocol.
  • SOCKS5, HTTP and HTTPS proxies, with or without a login and password. You can paste a proxy string from the clipboard. The site name is passed to the proxy, and the proxy looks up the address itself.
  • If the proxy is unreachable, connections don’t go direct. UDP and QUIC are blocked for apps on a proxy.
  • Four firewall modes: Proxy Only, Ask, Silent, Block All.
  • A connection monitor with a traffic map, and flags for connections around the proxy, with a tip on how to close them.
  • The menu bar icon: status, mode and the proxy’s external IP.
  • Import and export of rules, diagnostics collection, automatic updates.
  • Interface in English and Russian.

Checked against the Routekeeper code (version 0.2.1 and the one after it) on October 4, 2026.
