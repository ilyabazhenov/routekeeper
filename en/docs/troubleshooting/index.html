When something doesn’t work

Start with the table of symptoms. Below are the macOS permissions, all of the app’s messages, reinstalling the extension, the lock when the settings can’t be read, diagnostics and how to report a problem.

First, open the Overview screen. At the top, it shows the most serious problem and a button that fixes it. If the cause isn’t clear, find your case in the table below.

Is Routekeeper to blame? Turn off the Routekeeper On switch in the menu of the menu bar icon. Rules stop applying, and all connections go direct, past the proxy. If everything works now, the problem is in your rules or the proxy. If not, it’s most likely the network or another program. Don’t forget to turn the switch back on.

macOS permissions

Routekeeper works through a network extension, and macOS asks for permission three times: to turn on the extension, to filter network content and to add a proxy configuration. Until all three are given, the Routekeeper window shows the welcome screen with steps instead of the sections. Installation is described step by step in the Quick start. Here is what to do if something went wrong.

You clicked “Don’t Allow”

  • In the window about filtering network content. Open the Routekeeper window. On the welcome screen, at step 2, click Turn On Filter again. macOS asks again. Click “Allow”.
  • In the window about the proxy configuration. The same way: step 3 → Turn On Proxy → “Allow”.

Where to allow the extension

You do this step in System Settings, and the path depends on your macOS version.

  • macOS 15 and later. System Settings → General → Login Items & Extensions → Network Extensions. Turn on Routekeeper. If the general list of extensions opens, switch it to By Category and open Network Extensions. The Open System Settings button on the welcome screen and Open Settings in the hint window take you straight there.
  • macOS 14. System Settings → Privacy & Security. Scroll down to the message that system software from developer Ilya Bazhenov was blocked from loading. Click “Allow” and enter the administrator password. Routekeeper’s hints describe only the macOS 15 path, so on macOS 14 open System Settings yourself. If there’s no message, click Try Again or Install at step 1: macOS shows it again.

In the list, the extension is called “Routekeeper Extension”, and in versions 0.2.x “Routekeeper Network Extension”. Only a user with administrator rights can allow the extension.

The extension was turned off in System Settings

If you turn Routekeeper off in the list of network extensions, the filter and proxy stop working, and the Routekeeper window shows the welcome screen again. At step 1, click Install or Try Again and turn the extension back on in the same list. If Routekeeper’s configurations were turned off or removed in System Settings → Network, open the Routekeeper window. If it shows the welcome screen, repeat steps 2 and 3. If not, and the status line says “Proxy provider isn’t running”, click Settings → Extension → Reinstall.

macOS asks for a restart

Sometimes, after the extension is installed, step 1 shows “Restart your Mac to finish installing.” Restart your Mac and open Routekeeper. After a restart, the extension, filter and proxy start by themselves. The Routekeeper window opens by itself only if Open at login is on (Settings → General).

A Mac managed by an organization

On a work Mac, an administrator can forbid system extensions or network filters with a management profile (MDM). Then the switch in System Settings is missing or can’t be turned on, and you can’t change this yourself. Contact your administrator.

Details: what to tell the administrator

Routekeeper installs a system network extension with two configurations: a network content filter (sockets) and a transparent proxy (app proxy). The developer’s Team ID is N577X226Q5. The extension’s identifier is app.getroutekeeper.mac.extension; in versions 0.2.x, it’s dev.ilyabazenov.appproxy.extension. The app must be in /Applications.

Other VPN programs and network filters can also get in the way: see Other VPNs and network extensions.

An app goes around the proxy

The quickest way to find the cause is the monitor. Open Monitor, type the app’s name in the search field and select its connection. The Decision field at the bottom says why the connection went this way: “rule: …” with the app and the address, “no rule — Proxy Only mode”, “Routekeeper is off” and so on.

  1. Does the app have a route? Where all of an app’s traffic goes is set in the Apps section, not in Rules. The app’s row should have a route like Proxy: …, and the switch on the right should be on. If the Decision field says “no rule”, there’s no route. How to add one: An app’s route.
  2. Is it the right app? Routekeeper recognizes an app by its signature. A beta version, a copy from another store or a second browser are different apps. Add the one you need.
  3. Is Include Child Processes on? Right-click the app’s row. If the item is off, the app’s helper processes and the programs it launches follow their own rules. In the Leaks section, such connections are marked Process outside the rule. For details, see Child processes.
  4. Did another rule take over the address? A rule for a specific address, or a service, wins over the app’s route. For example, the “Russian sites” service with the Direct route, or the rule *.example.com → Direct, sends these addresses direct even for an app on a proxy. The Decision field shows this rule. The order is described in Which rule wins.
  5. Does the connection have a site name? Domain and service rules apply only when the app passed a name. Connections to a bare IP and most QUIC connections carry no name and follow the app’s route. If you’re counting on a service rule and the browser’s route is Direct, you need the recipe for a video service. For details, see Rules by site name.
  6. Is it an old connection? Open connections don’t move to a new route. Restart the app.
  7. Is going direct allowed when the proxy fails? If Settings → Network → If the proxy is down, go direct is on, connections go direct while the proxy is unreachable.
Details: what always goes direct
  • Connections to the same Mac (127.0.0.1, ::1), that is, loopback. There are built-in rules for this, and also the Leave localhost alone switch in Settings → Network.
  • Connections from any app to the address and port of a proxy added to Routekeeper. The Decision field says “connection to the proxy server”.
  • Routekeeper’s own connections: proxy checks, updates, service lists.
  • UDP DNS queries to port 53 from an app on a proxy: they’re let through directly and flagged as DNS around the proxy. For a browser, there’s a recipe.
  • UDP from an app on a proxy if that proxy has Block UDP and QUIC off. Such connections are flagged as UDP around the proxy.
  • New connections in the first seconds after the extension restarts or updates: see Limitations.

What Routekeeper flags as a connection around the proxy and what it doesn’t is described in What Routekeeper notices and what it doesn’t.

You see them in three places: next to the Check button in the Proxy section, in Monitor (the Route column shows Error, and the reason is in the connection’s details) and in the notification “…: proxy failed”.

Reinstalling and stopping the extension

The extension’s status is shown in Settings → Extension, in the Status section. If everything is fine, it says: Network extension “Active”, Filter “On”, Proxy “Running”. The Extension version is shown there too.

Reinstall

This helps when the extension has stopped responding, for example after an update.

  1. Open Settings → Extension and click Reinstall. The Reinstall Extension button on the banner and in the icon’s menu does the same.
  2. Routekeeper removes the extension and installs it again right away. For a few seconds, the filter and proxy are off: open connections through the proxy break, and new ones go direct during this time. Then the filter and proxy turn on by themselves.
  3. If macOS asks you to allow the extension again, allow it as you did during installation (permissions).

Rules, proxies and passwords are kept when you reinstall. If the “The network extension isn’t responding” banner doesn’t go away, restart your Mac.

Stop…

Settings → Extension → Stop… → Stop. Routekeeper’s filter and proxy are turned off at the system level. Apps start going online directly, past the proxy, and firewall rules stop applying. The extension stays installed, and the rules stay on disk. After that, the Routekeeper window shows the welcome screen.

The Routekeeper On switch doesn’t undo “Stop…”. It only turns the rules on and off inside a running filter and proxy. To bring the filter and proxy back after you stopped them, open Settings (icon’s menu → Settings…) → Extension and click Reinstall: after reinstalling, Routekeeper turns them on by itself. If the window shows the welcome screen with the Turn On Filter or Turn On Proxy buttons, you can click those too.

How the switch, “Stop…” and “Delete…” differ is summed up in a table in How to turn it off.

All connections are blocked

The banner “Settings couldn’t be read, all connections are blocked” means that the network extension couldn’t read the file with your rules and proxies. To make sure nothing goes around the proxy, Routekeeper then blocks everything. Only connections within this Mac, Routekeeper itself and the system DNS service are let through. This behavior appeared in the version after 0.2.1.

Why it happens

  • An older version of Routekeeper was installed over newer settings. The newer version may have saved the settings in a form the older one doesn’t know. Then the banner says: “They were saved by a newer version of Routekeeper”.
  • The settings file is damaged. Then the banner says: “The settings file is damaged”.

What to do

  1. Click Check for Updates on the banner. Routekeeper itself is still allowed to go online in this state. Install the new version: it will read the settings, and everything will work as before.
  2. If there’s no update or it didn’t help, click Reset Settings… → Reset. Your rules and proxies are deleted, and apps go direct until you set them up again.
  3. The reset doesn’t delete the old file: it stays next to the new one, named config.broken-number.json, in the /Library/Application Support/Routekeeper folder.

While the settings can’t be read, you can’t change them: Routekeeper answers “Routekeeper couldn’t read its settings, so they can’t be changed…”. You can turn Routekeeper off with the switch, but only until the extension restarts. After that, everything is blocked again.

Don’t install an old version over a new one. If you need to go back, save your rules first: Rules → Import and Export → Export… (proxy passwords aren’t saved to the file). For details, see Import and export.

Details: the backup and version 0.2.1

Only an administrator can open this folder. To see what’s in it:

sudo ls -l "/Library/Application Support/Routekeeper"

The config.broken-…json file is JSON with your rules, proxies and settings. It has the proxy passwords in plain text, so don’t attach it to a public bug report. The number in the name is the time of the reset in seconds since 1970.

Version 0.2.1 has no lock. It renames an unreadable file to config.broken-…json in the /Library/Application Support/AppProxy folder, and Routekeeper starts with clean settings: all apps go direct.

Collect diagnostics

A diagnostics archive helps work out what the problem is. Routekeeper doesn’t send it anywhere: the archive simply appears on your Desktop.

  1. Open the Routekeeper window. In the menu bar at the top of the screen, choose Help → Collect Diagnostics…. Or open Settings → Extension and click Collect… in the Diagnostics section.
  2. After a few seconds, Finder shows the file Routekeeper-diagnostics-date time.zip on the Desktop.
  3. Unzip it and look through it before you send it to anyone.

What’s in the archive

FileWhat’s inside
info.txtThe Routekeeper and macOS versions, the status of the extension, filter and proxy, the mode, the number of rules. For each proxy: its name, type, server address and port, and the result of the last check.
config.jsonRules, proxies and settings. There are no passwords, but there are server addresses and logins.
connections.jsonThe last 500 connections: app, address, port, route, error.
log.txtRoutekeeper’s internal log for the last 30 minutes, including the addresses that apps connected to.

The archive contains personal data: the addresses of sites you opened, and proxy addresses and logins. Bug reports on GitHub are public. Before you attach the archive, remove from it anything you don’t want to show.

Details: the log without an archive

If the Routekeeper window doesn’t open, you can save the log with a command in Terminal. The file appears on your Desktop.

log show --last 30m --info --predicate 'subsystem == "app.getroutekeeper.mac"' > ~/Desktop/routekeeper.log

For versions 0.2.x, the subsystem has a different name:

log show --last 30m --info --predicate 'subsystem == "dev.ilyabazenov.appproxy"' > ~/Desktop/routekeeper.log

Report a problem

Bugs and suggestions go to the project’s GitHub Issues. You need a GitHub account.

  1. Check whether your case is on this page or in Limitations.
  2. If the problem happens again, collect diagnostics right after it shows up, and look through the archive.
  3. In the Routekeeper window, choose Help → Report a Problem…. A form for a new issue opens in the project’s GitHub Issues.
  4. Write down:
    • the Routekeeper version: it’s in Settings → General → Version, for example “0.2.1 (10)”;
    • the macOS version and the Mac model: Apple menu → “About This Mac”;
    • the mode and the proxy type (SOCKS5, HTTP or HTTPS), without the address or password;
    • what you did, step by step, what you expected and what happened.
  5. Drag the diagnostics archive into the message field.

Everyone can see reports on GitHub. Don’t paste passwords, keys or addresses you don’t want to show. If you can’t share the archive, describe the problem without it and say that you have the archive.
